

## 1. 功能目标

开发一个通用格式转换平台，放在导入功能中。

目标：
用户上传一个文件，系统自动识别文件格式，选择目标格式后，通过转换引擎完成转换，并提供结果下载。

产品定位：
类似 CloudConvert / Smallpdf 的简化版本。

第一阶段只实现核心转换能力，不追求覆盖全部格式。

# 4. 核心设计原则

## 4.1 转换器插件化

必须设计统一 Converter 接口。


示例：

```ts
interface Converter {

    sourceFormat:string;

    targetFormat:string;


    convert(
        input:string,
        output:string
    ):Promise<void>;

}
````

每一种转换都是一个插件。

例如：

```
converters/

pdf-to-docx.ts

docx-to-pdf.ts

pdf-to-image.ts

image-to-pdf.ts

xlsx-to-pdf.ts
```

新增格式时：

只增加 Converter。

禁止修改核心流程。

# 6. API设计

## 上传文件

POST

```
/api/files/upload
```

返回：

```json
{
 "fileId":"xxx",
 "format":"pdf"
}
```

---

## 创建转换任务

POST

```
/api/tasks
```

参数：

```json
{
 "fileId":"xxx",
 "targetFormat":"docx"
}
```

返回：

```json
{
 "taskId":"xxx",
 "status":"waiting"
}
```

---

## 查询任务

GET

```
/api/tasks/{id}
```

返回：

```json
{
 "status":"processing",
 "progress":60
}
```

---

## 下载

GET

```
/api/files/{id}/download
```

# 7. Worker设计

Worker负责：

1. 获取任务

2. 锁定任务

3. 调用Converter

4. 保存结果

5. 更新状态

流程：

```
WAITING

↓

PROCESSING

↓

SUCCESS

```

失败：

```
FAILED
```

必须记录：

错误原因。
