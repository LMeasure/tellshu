## 2. 实际 API 契约、状态码与错误详情（已确认）

`POST /api/ai/study-notes`，body = **完整字幕 JSON**（`{transcript:{language,duration,segments}}`，不是 ID）。响应 `text/event-stream`：

| 阶段 | 情况 | 状态/载体 |
|---|---|---|
| 写 SSE 头前 | 未配置 AI | **503 JSON**（code 缺省）→ UI 空态「AI 学习稿生成未接入」 |
| 写头前 | 请求体不符 / 段数 >1200 | **400 JSON** |
| 写头前 | **限流 10 次/小时/IP** | **429 JSON**（code=`rate_limited`，文案「请求过于频繁，请在 N 秒后重试」） |
| 写头后 | 逐字增量 | SSE `data:{"type":"delta","text":…}` |
| 写头后 | 成功 | SSE `data:{"type":"done","note":{四要素}}` |
| 写头后 | 首 token >30s | SSE error `timeout_first_token` |
| 写头后 | 总流式 >120s | SSE error `timeout_stream` |
| 写头后 | LLM HTTP 错误 / 返回不可解析 JSON | SSE error `upstream` |
| 写头后 | 到 LLM 网络失败 | SSE error `unavailable` |
| 写头后 | 客户端断开 | 无事件（静默 end） |
| 流结束但无 done | 服务端异常断流 | 前端抛 `incomplete_stream` |

**限流机制（重点）**：先 `count += 1` 后判断（**429 也占额度**）；本地所有请求经 4174 代理后同源同 IP ⇒ **今天 15:16 我的 E2E 生成调用与用户的点击共用同一个 10 次/小时桶**，桶窗口从桶内第一次请求起算 1 小时。响应头带 `X-RateLimit-Limit / Remaining / Reset`（DevTools Network 可直接读余量与重置时刻）。

## 3. 三层证据

### 前端（实读）
- `StudyNotePanel.tsx`：挂载只读库；`generating` 态显示累计字符；失败走 `ErrorState`（message 透传）；503 且非 `backend_unreachable` 走「未接入」空态。
- `llmClient.ts`：fetch + ReadableStream 手工解析 SSE（`\n\n` 分块、坏行跳过）；非 2xx 解析 JSON error 体透传 message/code。
- `generate.ts`：done.note → 契约校验（坏项静默丢弃、四要素全空判败）→ 词汇回匹字幕段 → 查本地词库记 `dict_key` → `upsertStudyNote(status='ready')`。
- `store.ts`：upsert 按 `transcript_id` 原地重置（保留 id/created_at），不追加。

### 服务端（实读）
- `routes/ai.ts`：上述契约全实现；客户端断开即 abort 上游。
- `llmStudyNote.ts`：system prompt 要求纯 JSON；剥 ```json 围栏；契约校验失败 → `LlmError('upstream','LLM 未返回可解析的学习稿结构（JSON 契约校验失败）')`。
- `llm.ts`：首 token 30s / 总流式 120s 双超时；上游错误带 HTTP 状态。
- `rateLimit.ts`：见上（429 计数、内存桶、单实例）。
