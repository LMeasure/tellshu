## 2. 抓取流程

管线已在 `server/src/scripts/crawl-books.ts` 实现并经过 Stage 1（10 本）验证。**本方案不新增机制，只规定顺序与门禁。**

```
① robots.txt 检查
      ↓ 失败/被禁 → 立即停止，不重试
② RDF metadata 拉取与解析
      ↓ 解析失败 → 记入失败清单，跳过该书
③ 版权过滤（口径 A）：language / rights / 卒年
      ↓ 任一不通过 → 记入失败清单，跳过该书（不下载正文）
④ 正文下载（HTTP Range 续传 + 重试退避）
      ↓ 终态失败 → 记入失败清单
⑤ 完整性校验（START/END 标记 + Content-Length + SHA256）
      ↓ 校验失败 → 丢弃并重下；二次失败则记清单
⑥ 写入 .crawl-cache/<id>.json（不进 git）
      ↓
⑦ ingest-books.py：切块 → embedding（本地离线）→ 事务化写入
      ↓
⑧ 全量 REINDEX HNSW
      ↓
⑨ 重跑阶段 B 参数验证 + 固定 Query 集回归
```

### 2.1 robots 检查

- 抓取前**先读** `https://www.gutenberg.org/robots.txt` 并缓存（脚本已实现，兼作 TLS 预热）。
- 该文件**仅**禁止 `/ebooks/search` 一类搜索路径；`/browse/scores/top` 与 `/cache/epub/...` **不在禁止列表**。
- 站点未声明 Crawl-Delay，仍自我限流：**每请求 0.8–2.0 s 随机延迟，且全局 ≤ 30 请求/分钟**（取更严），**并发 ≤ 5**。
- 真实浏览器 User-Agent；不伪装搜索引擎、不使用多账号、不使用代理。
- **门禁**：若 robots.txt 变更并禁止上述路径 → **立即停止整批抓取**，不逐本重试。

### 2.2 RDF license 检查

- 拉取 `/cache/epub/<id>/pg<id>.rdf`，解析 `<dcterms:rights>`、`<dcterms:language>`、
  `<pgterms:agent>`（含 `<pgterms:deathdate>`）与 `<marcrel:*>` 贡献者。
- **rights 只做记录，不做放行依据**。常见文本「Public domain in the USA」**只在美国成立**；
  中国为「终生 + 死后 50 年」。**不得因站点声明 PD 就放行。**
- **门禁**：RDF 拉取失败或关键字段（title / language / authors）缺失 → 记失败清单并跳过，**不得推断补全**。

### 2.3 author death year filter（口径 A）

一本书**全部满足**才下载正文：

1. `language = 'en'`；
2. **每一位**作者/贡献者（含 `marcrel:*`）都能解析出真实 `<pgterms:deathdate>`；
3. 所有卒年最大值 **≤ 1975**；
4. 缺卒年 / 无法解析 / 语言不符 → 跳过并记原因码（`death_year_after_limit` / `missing_death_year` / `language_not_en`）。

**证据不足 = 不放行。宁可少收一本，也不凭推断入库。**

### 2.4 Range 下载

- 正文走 **HTTP Range 续传**：已有字节数 > 0 时发 `Range: bytes=<have>-`，合并 206 响应。
- 遇 `416 Range Not Satisfiable` 视为已收满（脚本已实现）。
- **理由**：实测本机到 Gutenberg 的首请求会被掐断，无续传会整本重来。

### 2.5 retry / backoff

- 连接超时 10 s、读取超时 30 s（脚本已设定）。
- 指数退避重试；尊重响应头 `Retry-After`。
- 触发限速惩罚时**自动把并发降半**（`concurrency = max(1, floor(c/2))`），不硬顶。
- **本机硬约束**：Node 访问 gutenberg.org 必须开 `enableUnsafeRenegotiation: true`
  （服务端要求 legacy TLS 重协商）+ keep-alive Agent + 首抓 robots.txt 预热，
  否则大面积握手失败。curl 不受影响（走 schannel），**不要用 curl 的成功推断 Node 也能通**。

### 2.6 checksum

- 正文落盘前校验三项：
  1. `*** START OF THE PROJECT GUTENBERG EBOOK ***` / `*** END OF ... ***` 标记齐全（多种变体正则）；
  2. 实际字节数与 `Content-Length` 一致；
  3. 计算 **SHA-256** 存入 `text_sha256`，作为后续幂等与变更检测依据。
- 任一项不通过 → 丢弃重下；二次失败记入清单，**不得用不完整的正文切块**。

### 2.7 入库与索引

- `ingest-books.py` 按书**事务化提交**，失败有清单。
- 先 `--backup-embeddings`（本次新增 37k 条，备份表会随之增大；**v1 备份表 `discovered_book_chunks_emb_v1` 保持不动**）。
- embedding 沿用 **`v2-title-author-chapter`** recipe，**模型不变**（`BAAI/bge-m3`，1024 维，本地离线，`HF_HUB_OFFLINE=1`）。
- **整表写入完成后必须 `REINDEX` 正式 HNSW 索引**（实测不重建会从 189 MB 膨胀到 247 MB）。
- 章节归属不可靠 → 写 `NULL`，**不猜**；无章节块**不删除**，只在查询时过滤。

## 4. 抓完之后必做（Stage C 的验收门禁）

1. **扩充固定 Query 集**：现有 16 条（分母 13）在 30 本下**分母太小**，1 条 = 7.7 pp。
   建议扩到 **≥ 40 条计入 Query**，否则命中率仍不具备决策价值。
2. **重跑阶段 B 参数验证**：规模跨过 50k，`m` / `ef_construction` / `ef_search` 的
   表现会整体改变，**不得沿用 24k 下的任何读数**。预设起点 `m=16 / efC=256 / efS=200`，
   **必须实测复核**。
3. **用 `EXPLAIN (ANALYZE, BUFFERS)` 确认实际走了哪个计划** —— 不要凭配置推断。
4. **回归红线**：不得静默返回空结果；不得用假数据兜底；实验副本不进生产。
5. **回填本文档 §1.2 的估算值**为实测值。

## 5. 风险与不确定项

| # | 风险 | 影响 | 缓解 |

| 1 | **embedding 耗时无实测基准** | 总耗时预期可能偏差数倍 | 先跑 2 本计时探针再回填 |
