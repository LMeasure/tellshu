## 2. 启动流程

### 2.1 PostgreSQL —— 正常情况下什么都不用做

服务是 `Automatic`，开机自启。当前实例起于 **2026-10-21 13:14:05**，至今未重启过。

只有确认它真的停了（`Get-Service` 显示 `Stopped`、无 5432 监听、`postgres.exe` 为 0）才需要启动，
且**必须开提权窗口**（你是 Administrators 组成员，但默认令牌未提权）：

```powershell
Start-Service postgresql-x64-18        # 提权窗口内
```

启动后确认三件事，缺一不可（不能只凭一条命令的返回判断成败）：
`Get-Service` 状态 = Running、`5432` 出现监听、日志出现 `database system is ready`。

### 2.2 检索 API（8000）

见 §0 命令块。三个环境变量**一个都不能少**：

| 变量 | 为什么必须 |
|---|---|
| `EMBEDDING_BACKEND=onnx` | 本机 Python 3.14 **没有装 `FlagEmbedding`**，只有 `onnxruntime`；不指定会启动失败 |
| `no_proxy=127.0.0.1,localhost,::1` | 本机有 `http_proxy`，不加本地请求会 502 |
| `HF_HUB_OFFLINE=1` | 离线取 tokenizer，不联网 |

启动耗时约 **6 秒**（ONNX 模型加载 2.7 秒）。模型：`bge-m3-onnx/model_int8.onnx`（569 MB）。

**必须后台常驻**：命令行工具在命令结束时会清掉整棵进程树，写成 `(cmd &)` 会被回收。

### 2.3 前端

```bash
npm run preview -- --port 4174 --strictPort
```

Vite 已配置代理 `/api/discover` → 8000。**换端口会作废 Service Worker / Cache / IndexedDB，不要换。**

## 5. 延迟口径 —— 两种，不能混着看

| 口径 | 实测值（2026-10-22） | 说明 |
|---|---|---|
| 回归端点（每条 3 次取后 2 次，热态） | HNSW P50 **7.39 ms** | 项目验收口径 |
| HTTP 压测第二轮（工作集入池后） | retrieve **9.27 ms** / e2e 27.69 ms | 比 B.11 基线（30.80 ms）**−69.9%** |
| 空闲约 12 小时后**单次**首触 | retrieve **73.02 ms** ❌ | **单次观测，未建立冷态基线**，不能当性能结论 |

**【推断】** 差别来自「工作集是否已驻留在 `shared_buffers`」——同一实例、同一配置，第二轮立刻回到 9.27 ms。
所以**第一次查询偏慢是正常的，跑几条热身就好**，不要据此判定配置失效。

## 6. 常见故障与处置

| 症状 | 原因 | 处置 |
|---|---|---|
| 请求 502 | 本机 `http_proxy` 把本地请求代理走了 | 加 `no_proxy=127.0.0.1,localhost,::1` |
| API 起不来，报模型/后端相关 | 没设 `EMBEDDING_BACKEND=onnx`（`FlagEmbedding` 未装） | 补上 env |
| 前端提示「后端没启动」 | 8000 没起来，Vite 代理兜底返回 503 `backend_unreachable` | 按 §2.2 拉起 API |
| 拉起后一会儿就没了 | 没用后台常驻，进程树被清 | 用后台常驻任务 |
| 首条查询几十甚至上百 ms | 冷启动，工作集未入池 | 热身几条再看；别当基线 |
| 5432 连不上 | PG 服务停了 | 提权 `Start-Service`；按 §2.1 三件事确认 |

## 7. PostgreSQL 操作红线

1. **不要手跑 `pg_ctl start/stop`** —— 现在归 Windows 服务管（账户 `NT AUTHORITY\NetworkService`），
   手跑会造成双账户争用同一数据目录。2026-10-20 17:05 两次
   `FATAL: the database system is starting up` 就是这么来的。
2. **不要手动删除 `D:\Program Files\PostgreSQL\data\postmaster.pid`** —— 现由运行中的实例持有。
3. **不要用 `restart`** —— 曾撞过 `ShmemIndex entry size is wrong`；要动就 stop → start。
4. **不要改 PG 配置**（`shared_buffers` / `effective_cache_size` 等）—— 改前需单独授权。
5. ⚠ **服务未配置失败恢复**（注册表无 `FailureActions`）⇒ **崩溃后不会自愈**，得人工发现。
