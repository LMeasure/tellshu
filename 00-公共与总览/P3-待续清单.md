### 步骤 1 · 创建 R2 桶 + 拿 API Token

**做什么**
1. 注册 / 登录 Cloudflare（**需支付方式**：R2 免费额度开通要求绑定支付方式，

| `AWS_SECRET_ACCESS_KEY` | R2 API Token 的 Secret Access Key | **是** |

### 步骤 7 · 数据发版流程（v1 → v2）

**核心设计：路径即版本。** 不需要迁移、不需要清理老数据。

```bash
# 1. 生成新数据到 v2（导出脚本的 OUT_DIR 改为 data/linguabase/v2/）
# 2. 上传时用新前缀（**不要**覆盖 v1）
export S3_PREFIX="linguabase/v2"
python scripts/upload_data.py

# 3. 前端把 DATA_VERSION 改成 v2，重新部署
#    src/data/dataClient.ts: export const DATA_VERSION = 'v2'
#    （若已完成「步骤 6 提案」里的 env 化，则改环境变量即可，不用改代码）

# 4. 观察一段时间确认 v2 无误后，再决定是否删 v1
```

**为什么这样设计**
- 老客户端继续读 `v1`，新客户端读 `v2`，**互不影响**，可灰度、可回滚。
- 分片带 `immutable` 一年缓存**不影响** SW 更新 —— SW 的缓存名带版本，失效由 `sw.js` 自己控制。

**验收标准**
- [ ] `https://<公开基址>/linguabase/v2/index.json` 200
- [ ] `.../linguabase/v1/index.json` **仍** 200（老版本没被破坏）
- [ ] 新构建的前端请求的是 `v2` 路径

## 附录 B · R2 CORS 配置模板

**方式一：Cloudflare 控制台**（R2 → 桶 → Settings → CORS Policy）粘贴：

```json
[
  {
    "AllowedOrigins": [
      "https://你的站点域名",
      "http://localhost:5173",
      "http://localhost:4173"
    ],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["Content-Length", "Content-Type"],
    "MaxAgeSeconds": 86400
  }
]
```

**方式二：命令行**（需 `aws` CLI 或 boto3，`--endpoint-url` 指向 R2）：

```bash
aws s3api put-bucket-cors \
  --endpoint-url "https://<account_id>.r2.cloudflarestorage.com" \
  --bucket shushu-data \
  --cors-configuration file://cors.json
```

> ⚠️ 别用 `"AllowedOrigins": ["*"]`。虽然省事，但等于把数据向任意站点开放，
> 且 `*` 与带凭证的请求不兼容。只放行你自己的域名 + localhost。
