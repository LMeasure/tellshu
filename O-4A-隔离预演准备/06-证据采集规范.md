# O-4A 第九轮 · 证据采集规范

> 配套：`04-并发测试套件.py`（`Evidence` dataclass 即本规范的程序化实现）、`02-O-4A-Runbook.md` §8。
> 原则：每个测试产生**独立、可关联到具体场景**的证据文件，**绝不只保存一个总 PASS/FAIL**。

---

## 1. 证据文件布局（第十轮：run_id 隔离，禁止不同运行互相覆盖）

```
evidence/
  <run_id>/                         # run_id = UTC时间戳_随机串，每次运行唯一
    T01.json ... T16.json, T12A~F.json   # 每场景一份，文件名 = test_id
    summary.json                    # 汇总：状态分类 + 每不变量逐项
  <run_id_2>/ ...                   # 另一次运行，绝不覆盖上一次
```
- 第十轮修复：`04-并发测试套件.py` 自动创建 `evidence/<run_id>/`，`--out` 只是根目录；历史上按 `test_id` 幂等覆盖的做法已废弃（会导致不同运行互相覆盖）。

---

## 2. 单测试证据字段（强制，缺一不可；与 04 `Evidence` dataclass 对应）

| 字段 | 类型 | 来源 / 采集点 |
|---|---|---|
| `run_id` | str | 运行批次唯一标识（防跨运行覆盖） |
| `test_id` | str | 场景编号（T01~T16、T12A~F） |
| `purpose` | str | 场景目的，回溯任务书 |
| `pg_version` | str | `SHOW server_version`（须 = 18.x，不符即证据无效） |
| `psycopg_version` | str | 启动时校验（须 ≥3.2.4） |
| `started_at` / `ended_at` | ISO8601 | 用例起止（UTC） |
| `sessions` | list[SessionResult] | **每会话**结构化：`label`/`role`/`backend_pid`/`txid`/`sql_log`/`sqlstates`/`outcome`/`completed` |
| `lock_wait_evidence` | list[{pid,wait_event_type,wait_event,lock_mode,relation,blocked_by}] | 提交前由 monitor 连接采样 `pg_locks`/`pg_blocking_pids` |
| `barrier_events` | list[{name,pid,role,event,at}] | 屏障四状态事件流（见 04c） |
| `notify_missed` | int | 通知丢失/超时重读次数（见 04c §4） |
| `sql_ae_coverage` / `spi_snapshot` / `channel_check` | str | 场景的 SQL-A~E / READ COMMITTED / channel 白名单映射（见 04b） |
| `final_snapshot` | {state, consumed_has_txid, consumed_has_xid} | 最终 `r2_evidence_consumption` 行 |
| `invariants` | {I1..I7: bool} | 七项不变量逐条 true/false（见 05） |
| `evidence_complete` / `missing_fields` | bool / list[str] | 证据完整性自检：缺字段清单 |
| `verdict` | 枚举 | `PASS`/`FAIL`/`NO_RUN`/`TIMEOUT`/`ABORT`/`PARTIAL`（见 §5） |

> 每会话的 txid 用 `pg_current_xact_id()`、PID 用 `SELECT pg_backend_pid()`、SQLSTATE 逐条捕获；不再用扁平 list 混淆会话归属。

---

## 3. 采集时点（确定性，非 sleep）

1. **开始时**：记录 `started_at`、各会话 `backend_pid`、各自 `pg_current_xact_id()`。
2. **执行中（提交前）**：monitor 连接调用 `sample_locks()` 采样未授予锁，得到 `lock_wait_evidence`（证明阻塞图 T2→T1 等）。
3. **异常时**：捕获 `e.sqlstate` 入 `sqlstates`，按 `expect_raise` 决定 ROLLBACK 并记录。
4. **结束时**：`ended_at`、读 `final_snapshot`、跑 `check_invariants()` 填 `invariants`、写 JSON。

> 锁等待证据体现「可观测锁状态」：例如 T02 应观测到 5 个会话 `wait_event_type='Lock'`，`blocked_by=[先获锁者pid]`，`lock_mode='RowShare'/'RowExclusive'`，`relation='r2_evidence_consumption'`；T11 同。

---

## 4. 关联性与可审计性

- 每个 `evidence/<test_id>.json` 顶部含 `purpose`（来自 `ScenarioDef`），可回溯到任务书 任务三 的具体路径。
- `summary.json` 列出每测试 `verdict` 与 `invariants` 逐项，供负责人逐项裁决，**不合并为单点结论**。
- 锁采样原始数据（若开启）按 `test_id` 落 `locks/`，与场景一一对应。

---

## 5. 失败判定与「不误判成功」纪律（第十轮强化）

`verdict` 判定优先级（`04-并发测试套件.py` 实现）：

| 优先级 | 条件 | verdict |
|---|---|---|
| 1 | `evidence_complete=False`（缺任一必填字段/会话数不符/会话无 PID 或 outcome） | `ABORT`（**缺证据绝不 PASS**） |
| 2 | 屏障/等待超时 | `TIMEOUT` |
| 3 | 执行器异常 | `ABORT` |
| 4 | 七不变量任一 false | `FAIL` |
| 5 | 任一会话 `outcome` 以 ABORT 开头 | `ABORT` |
| 6 | 屏障 `completed<total`（参与者崩溃） | `PARTIAL` |
| 7 | 全部通过 | `PASS` |

- 未执行的用例：`NO_RUN`（`--only` 未选中或运行前中断），**绝不**计入 PASS。
- 证据文件落盘失败 ≠ 数据库事务失败：DB 结果照记，落盘异常令 `verdict=ABORT`，写 stderr。
- `pg_version` 非 18.x ⇒ 该批证据整体无效，须重建隔离实例。
- **不同运行不覆盖**：写入 `evidence/<run_id>/`（§1）；`summary.json` 按 run_id 独立。
- `summary.json` 汇总 `PASS/FAIL/TIMEOUT/ABORT/PARTIAL/NO_RUN` 各类计数，逐用例列 `verdict`/`invariants`/`evidence_complete`/`missing_fields`，供负责人逐项裁决，不合并为单点结论。
