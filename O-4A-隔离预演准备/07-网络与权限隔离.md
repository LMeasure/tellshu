> 配套：`02-O-4A-Runbook.md` §3.3/§5、`03-init-cleanup.sql`（段 A/F）、`04-并发测试套件.py`。
> 本轮未执行。本文件为隔离预演的**设计资产**：网络边界 + 最小权限角色矩阵 + 密钥管理纪律。

## 1. 网络隔离（三层边界）

| 边界 | 设计 | 阻断项 |
|---|---|---|
| ① 实例绑定 | 预演 PG 仅监听 `127.0.0.1:$O4A_PORT`（默认 5433），`listen_addresses='127.0.0.1'` | 公网/跨主机不可达 |
| ② 主机防火墙 | `iptables/nftables` 拒绝非 `lo` 来源到 `$O4A_PORT`；若存在 overlay 网段，仅放行预演专用网段 | 非授权主机连接 |
| ③ 数据/服务隔离 | 不挂载生产数据目录；不连 R2；不建 `cross_gen_*`/`backup_manifests`/`recovery_runs`；与 DB-A(恢复目标)/DB-B(审计) **物理隔离** | 误触生产/备份链路 |

> 明确不与任务书禁止项冲突：本预演**不连接 R2**、**不使用真实凭证**、**不连接生产或现有业务数据库**。

## 2. 最小权限角色矩阵（第十轮：5+2 角色职责隔离）

| 角色 | 登录 | 职责 | 可写（精确 GRANT） | 可读 | 明确禁止 |
|---|---|---|---|---|---|
| `shutree_fn_owner` | ❌ NOLOGIN | 对象属主 + TRG-01 SECURITY DEFINER 执行主体 | 以属主身份在触发器中 UPDATE consumption | 全部 | 不直接登录；无 BYPASSRLS |
| `shutree_fixture_admin` | ✅ | 合成数据种子 / 场景清理 / 证据采证（**业务事务之外**） | 闭环全部表 + 协调表 INSERT/UPDATE/DELETE/TRUNCATE | 全部 | 不参与任何业务测试事务 |
| `shutree_evidence_collector` | ✅ | 采集主体：仅 INSERT record | `r2_evidence_record` INSERT | 闭环表 | 无 consumption 写；无 DELETE/TRUNCATE/UPDATE/DDL |
| `shutree_evidence_verifier` | ✅ | 复核主体：仅 INSERT verification（触发 TRG-01） | `r2_evidence_verification` INSERT + 协调表 INSERT/UPDATE | 闭环表 | **无 consumption UPDATE**（T12 核心）；无 DELETE/TRUNCATE/DDL |
| `shutree_monitor` | ✅ | 只读诊断：`pg_locks`/`pg_stat_activity` | 无（pg_monitor 角色只读系统视图） | 闭环表 + 协调表 + 系统视图 | 所有业务写 |
| `shutree_app` | ✅ | 只读业务数据 | 无 | 闭环表 | 所有写 |
| `shutree_admin` | ✅ SUPERUSER | 仅事后对账/审计 | 全部（旁路，见 §4） | 全部 | 不参与预演写入（如实登记旁路） |

### 2.1 逐项 GRANT / REVOKE 对照（与 `03-init-cleanup.sql` 段 F 一一对应）

| 对象 | 操作 | 授予/回收角色 | 目的 / 对应测试 |
|---|---|---|---|
| SCHEMA shutree_sec / app | `REVOKE ALL FROM PUBLIC`；`GRANT USAGE` 给 5 业务角色 | 全体 | 禁止 PUBLIC 建对象/越权 |
| 全部闭环表 | `REVOKE ALL ON ALL TABLES ... FROM PUBLIC` | PUBLIC | 默认最小 |
| 证据表/record/verification/consumption | `GRANT SELECT` | app/monitor/fixture/collector/verifier | 只读 |
| 全部闭环表 + 协调表 | `GRANT INSERT,UPDATE,DELETE,TRUNCATE` | **仅 fixture_admin** | 种子/清理专用 |
| `r2_evidence_record` | `GRANT INSERT` | collector | 采集写入 |
| `r2_evidence_verification` | `GRANT INSERT` | verifier | 复核写入（触发 TRG-01） |
| `r2_evidence_consumption` | **不 GRANT UPDATE/DELETE/TRUNCATE 给任何业务角色** | — | append-only 槽位；T12/T12A~F 验证 |
| `rehearsal_barriers` | `GRANT SELECT,INSERT,UPDATE` | verifier/collector | 屏障到达/完成登记 |
| `rehearsal_barrier_events` | `GRANT INSERT` | verifier/collector | 屏障事件 |
| `pg_monitor` 内置角色 | `GRANT pg_monitor TO shutree_monitor` | monitor | 锁/活动只读诊断 |
| TRG-01 函数 | `REVOKE ALL ... FROM PUBLIC` | PUBLIC | SECURITY DEFINER 默认 PUBLIC EXECUTE，必须回收 |

> append-only 强制：`evidence_signing_key`/`r2_evidence_record`/`r2_evidence_verification` 对业务角色 `REVOKE UPDATE,DELETE,TRUNCATE`；`consumption` 状态推进仅由 `shutree_fn_owner` 属主身份在 TRG-01(DEFINER) 内完成。T12/T12A~T12F 负向 + T12F 正向共同验证该锚点：普通角色直改被拒、合法入口可推进。

## 3. 密钥与凭证管理（严禁聊天索取）

- 所有角色密码经 **环境变量 / secret 管理器**注入（如 `VERIFIER_PW`、`COLLECTOR_PW`、`ADMIN_PW`），脚本以 `:'pw_var'` 占位从环境读取。
- **绝不**要求负责人在聊天中发送数据库密码、SSH 密钥或其他秘密（任务书硬约束）。
- `.env`/secret 文件一律不入库（`.gitignore`）；本交付包任何文件均不含真实凭证。
- 隔离实例采用 `trust` 仅限 `127.0.0.1` 作为简化；生产形态须改 `scram-sha-256`（见 08 §mTLS/短期令牌）。

## 4. 超级用户旁路（诚实登记，非 `[DB]` 保证）

按 V1.2.30 §13 #10 / §10.2：超级用户可 `DISABLE TRIGGER`/`ALTER INDEX INVALID`/直连 DML，DB **无法硬阻止**。本隔离预演对策：
- 预演启动自检 `pg_trigger.tgenabled`、`pg_index.indisvalid`；
- 测试框架对关键约束做「存在性断言」；
- 旁路事件记入 `admin_action_log`（扩展预演再补）。
- 本预演不依赖消解该旁路；如实登记为**独立阻断项（真实实施层面）**，不计入本轮 P0/P1（因其不影响 SQL-A~E 闭环正确性证据）。

## 5. 管理权限旁路边界（T12 不得扩大解释）

任务四要求把「普通业务角色权限边界」与「管理权限旁路」分开登记：

| 风险 | 由 T12 普通角色测试覆盖？ | 性质 |
|---|---|---|
| collector/verifier/app 直改 consumption（UPDATE/DELETE/TRUNCATE） | ✅ 是（T12/T12A~D，期望 42501） | DB 权限可硬阻 |
| 业务角色改触发器/函数/DDL | ✅ 是（T12E，期望 42501） | DB 权限可硬阻 |
| 正常受控入口仍合法推进 | ✅ 是（T12F） | DEFINER 触发器 |
| **SUPERUSER** 直连 DML / `DISABLE TRIGGER` / 改系统目录 | ❌ 否（单独登记） | DB 无法硬阻止（V1.2.30 §13 #10），生产治理层 |
| **表所有者**（fn_owner）绕过 | ❌ 否（单独登记） | 属主天然有权限；本预演属主仅用于 DEFINER 受控入口 |
| `ALTER TABLE ... DISABLE TRIGGER` 权限 | ❌ 否（单独登记） | 需表属主或 SUPERUSER，业务角色无 |

**结论纪律**：T12 系列只证明「普通业务角色不能绕过受控入口」，**绝不**扩大解释为「超级用户也无法绕过」。超级用户/属主旁路是独立的生产实施层治理问题，不计入本轮 P0/P1，但如实登记为残留风险。

> 第十轮已删除第九轮的「单角色回退」方案：不得低于权限隔离运行全部会话；缺角色 DSN 套件拒绝启动（退出码 92）。
