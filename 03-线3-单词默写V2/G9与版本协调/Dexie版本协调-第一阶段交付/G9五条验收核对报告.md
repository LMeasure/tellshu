## 逐条展开（已有证据 / 缺失证据 / 解除阻塞条件）

### 标准 1：指定 `spellingErrorEvents` 版本 + 完整 `stores()` 声明

- **已有证据**：
  - `Dexie版本协调-G9-D9-结论.md` §二：版本分配表明确 `spellingErrorEvents` → **v14**（原生 IDB 140），纯新增表、无 upgrade 回调、存量零触碰。
  - 实施 A 已落地：`src/services/storage/web.ts` 新增 `version(14)` stores 字符串 `&event_id, owner, word_id, session_id, kind, occurred_at, status`；`src/domain/types.ts` 新增 `SpellingErrorEvent` 接口与 `StorageSchema`/`PrimaryKeyMap` 登记。
- **缺失证据**：
  - 「完整 `stores()` 声明」未经**架构负责人书面确认**；打字链路 `Phase1.2.2` §6.5 仅给索引清单草案，本轮列为**待确认草案**，不作为已定声明。
  - v14 `kind` / `status` 枚举取值为**实施草案**（`'wrong'|'skip'|'unavailable'` / `'pending'|'settled'|'aborted'`），待架构负责人确认（授权清单 Q2 / 结论 §九 item 3）。
- **解除阻塞条件**：架构负责人书面确认 v14 完整 `stores()` 声明（含字段与索引）；确认枚举取值。确认后本标准可勾选。

### 标准 2：v12 表述以哪份为准 + 是否合并版本

- **已有证据**：
  - 结论 §一/§二：`v12` = 对 `readings/recitations/transcripts/studyNotes/annotations` 补 `owner` 索引（非新增表，5 表自 v2/v7/v5/v9 已存在）；书籍 v12 / 默写 v14 **分版本、不合并**。
  - 代码佐证：`web.ts` 现有 `version(11)`；实施 A 的 `version(12)` 仅补 owner 索引、`version(14)` 新建 spellingErrorEvents，二者分属不同版本号。
  - V1.2.11 收敛稿 §七 已裁定 v12/v13 归属书籍资产。
- **缺失证据**：无（文本层结论成立）。
- **解除阻塞条件**：本条文本层已满足，不需额外证据；但仍受「五条全勾 + 书面记录 + 负责人确认」总闸门约束，不单独导致 G9 关闭。

### 标准 3：×10 夹具基线、版本序列、维护人；覆盖全部 v11 表与索引

- **已有证据**：
  - 结论 §二：迁移序列 `…→110(v11)→120(v12)→130(v13)→140(v14)`；x10 映射 `version(n)→n×10`；夹具 v12=5 表加索引+补 guest、v13=owner 默认+注册事件、v14=新建表；v11 全部表/索引须原样保留；`v110→v120` 夹具顺序「仍适用」。
  - 结论 §三：维护人以**角色身份**登记（执行人/审核人/冲突解决人），见 `v12-v13-v14-责任矩阵.md`。
- **缺失证据**：
  - 「覆盖全部 v11 表与索引」为**设计声明**，无夹具实测；`v110→v120` 顺序「仍适用」同为设计判断（结论 §二状态声明）。
  - 维护人前版为 `D3` 编号，本版 §三补为角色身份，但**具体自然人/账号待指派**（结论 §九 item 2）。
- **解除阻塞条件**：夹具经 C47–C56 等迁移自动化实测覆盖全部 v11 表与索引；项目负责人指派具体自然人（结论 §九 item 2）。

### 标准 4：blocked/versionchange 落地归属 + 升级窗口双标签中断/恢复约定

- **已有证据**：
  - 落地归属已明确：结论 §三 v13 执行人=统一书籍资产架构实施方（`blocked`/`versionchange` 落地）；审核含单词默写 V2 实施方（U16 影响面复核）+ 项目负责人。
  - 实施 A 已落地：`web.ts` 在 `db` 构造后注册 `db.on('blocked')`/`db.on('versionchange')`（内 `db.close()`）。
  - 本交付包已产出 `U16-升级中断恢复协议.md`（七场景设计）与 `C09-T29-L2-跨标签单写者锁设计.md`（锁覆盖）。
- **缺失证据（按标准 4 的 "and" 关系，后半段缺失即判未满足）**：
  - **恢复约定未成立**：`Phase1.2.2` U16「当前无实测、无约定」；`spellingErrorEvents` 表虽已建（v14）但**写逻辑未落地**；`drainPendingErrors()` **无启动钩子**（`main.tsx` 无该调用，Phase1.2.3 L51）；L2 写锁在 D4 仍**待批准**。
  - U16 仅处设计提案阶段，未批准为生效协议、未实现、未验证 → 仍不能证明「升级窗口内被 `db.close()` 中断不丢事件」。
  - 跨标签残留窗口 C09/T29（事件未落盘、另一标签已提交）经 `lock_epoch` **降级但未消除**（U1），彻底消除需 L3 跨表事务（不推荐本轮）。
- **解除阻塞条件**：v14 写逻辑落地 + `drainPendingErrors()` 启动钩子 + U16 恢复链成文（已产出设计稿，待批准）+ 真机双标签升级窗口回归（C61/C63/C64）通过 + 审核人书面确认。完成后本标准方可勾选。
