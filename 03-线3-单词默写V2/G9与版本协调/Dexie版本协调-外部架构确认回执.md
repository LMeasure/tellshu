## 7. T-A 未提交事件窗口 与 C09/T29 跨标签残留窗口 的可靠持久化方案及验证标准

### 7.1 T-A 未提交事件窗口

**定义（证据）**：事务 T-A = `insertIfAbsent(E)` 将错误事件落入 `spellingErrorEvents`（`status='recorded'`，Phase1.2 L140/L199）。「未提交窗口」指 T-A 尚未提交 IDB 的时段；升级中断 / `db.close()` 可致事件行不存在（Phase1.2.3 L338）。

**可靠持久化方案（设计提案）**：
1. **幂等落盘**：`insertIfAbsent` 以 `event_id` 主键，重跑同 `event_id` 为 no-op。
2. **顺序硬约束**：T-A 完成方可 T-B（会话凭证变更）/ T-C（status）；T-B 前置屏障先读已落盘事件（Phase1.2 L160、Phase1.1 C08）。
3. **升级窗口恢复（U16）**：`db` 重开后 `drainPendingErrors()` 按 `spellingSessions` 内嵌 queue + `last_error_settled_at` 高水位重放 T-A→T-B；**不得依赖内存 L2 队列**（进程被杀即丢）。
4. **持久化前置**：待写事件须在 `db.close()` 前已进入 `spellingSessions` 持久化 queue（或先于 drain 落盘），使重放依据存在。

**验证标准**：
- 自动化：注入「T-A 提交 / T-B 未提交 + versionchange」崩溃（C57/T80，Phase1.2.3 L351/L421），重连后 drain 恰一次重放、cc=0、指标一致 → 目标 `【待自动化】→通过`。
- 真机：升级期间一标签 in-flight T-A，重开验证事件恰一次落盘、无重复无丢失 → `【待真机】`。

| 四态 | 状态 |
|---|---|
| 设计接受 | ⚠️ 雏形具备，但 U16 恢复链「当前无实测、无约定」（Phase1.2.2 L524），须成文 |
| 代码实施 | ❌ 未实施（`spellingErrorEvents` 表未建、无 drain 钩子） |
| 自动化测试 | ❌ 待自动化（C57/T80 标 `【待自动化】`） |
| 真机验证 | ❌ 待真机 |

### 7.2 C09 / T29 跨标签残留窗口

**定义（证据）**：两标签同会话；A 的 error `add` 未落盘、B 的 `submitAttempt` 已提交 → SRS 误交接不可逆、错词计数可能偏差（Phase1.1 L393/L443/L479）。

**现状（设计层已裁定）**：D4「接受并如实标注」（Phase1.1 L494）；L2 `lock_epoch` 仅降级不消除（Phase1.2.1 L659）；§7.3 L432 明示「仍须补充可靠持久化/协调设计，并完成自动化及真机验证」。

**可靠持久化 / 协调方案（设计提案，含范围声明）**：
1. **单会话单写者跨标签锁（消除残留的唯一根本手段）**：以 `navigator.locks` 或 IDB 协调记录（`tab_id` + 心跳）保证同一 `(owner, session_id)` 任意时刻仅一个标签可写；异标签写请求被拒/重定向，而非仅降级。
2. **产品声明 + UI 提示**：「不支持多标签同时练习同一会话」（Phase1.2 L282 接受条件①）。
3. **诚实标注**：T29 标「已知残留、不通过」而非跳过（Phase1.2 L282⑤）。

> ⚠️ **范围声明**：方案 1（单写者锁）超出当前 D4「接受残留」边界，属**范围扩大**。若要求「可靠方案 = 零残留」，须先由负责人修订 D4 并接受该范围；否则 C09/T29 仅能以「接受残留 + 标注」闭环，**不得宣称已消除**。

**验证标准**：
- 自动化：双标签并发 T-A(A)/submitAttempt(B) 交错注入；断言无重复计数、残留不超过 D4 接受口径。
- 真机：双真实标签同会话同时操作；测残留率并如实记录。
