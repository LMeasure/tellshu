### 1.4 产品规则逐条落实
| 规则 | 落点 |
|---|---|
| 1 逐字母检测、错误即时事件 | `applyLetter` wrong 分支 → `submitLetter` 同事务 `addIfAbsent` |
| 2 每错误字母计一次 | 1 字母 = 1 `event_id` = 1 行；同词错 2 字母 = 2 行 |
| 3 同词合并、次数 +N、更新最近时间 | `spellingWrongBook.aggregateWrongWordBook` |
| 4 立即播放错误提示音 | `SpeechService.playErrorTone()`，仅新错误事件触发（重放不重复播） |
| 5 输入进度清零 | `typed_prefix = ''`，持久化并刷新可复现 |
| 6 连续正确次数归零 | `consecutive_correct = 0` |
| 7 单字母不是完整答题提交 | `is_full_attempt=false`，不调 `applyAttempt` |
| 8 不污染 SRS / total_attempts | 错误分支不动 attempts、不产生 `srs_due` |
| 9 错词本独立于 SRS 错题 | 只读 v14 事件表，不碰 `in_wrong_pool`/`recordQuiz` |
| 10 事件 ID 幂等 | `evt:letter:<request_id>` + `addIfAbsent` + 凭证二次检查 + `processed_letters` 回放 |

## 3. 架构与兼容性说明（不虚报）

- **V1/V2 并存**：`submitAttempt` / `applyAttempt` / `judgeSpelling` 保留作兼容 API，既有自动化用例仍全绿；**页面主输入已切到 V2**，V1 整词判定不再是页面路径。
- **旧会话恢复**：V1 会话没有 `typed_prefix`/`processed_letters`，按 `''`/`{}` 处理，即从第一个字母重新开始，符合规则 5；无需回填、无需迁移。
- **事务与锁**：`submitLetter` 与 V1 `atomicSubmit` 共用同一 `atomicBatch` 事务骨架、`assertLockInTransaction`、`validateEventRow`（owner/session/tab/epoch）、凭证二次检查、`applied_error_event_ids` 幂等；U16 五步链与 `converged` 闸门未改。
- **不宣称的事**：不宣称 `lock_epoch` 消除了 T-A 未落盘窗口（该窗口由跨表事务串行化关闭）；不宣称「升级中断绝对不丢事件」；不宣称逐字母提示音在本机被「听到」（浏览器无音频采集，自动化层以 `playErrorTone` 调用计数断言触发）。
- **平台红线**：`AudioContext` 只在 `src/services/speech/web.ts`；页面只调 `SpeechService` 接口；图标按钮保留 `aria-label`/`title`；技术栈版本未升级。
