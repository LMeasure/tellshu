## 3. `src/domain/spelling.ts` 提供了什么

纯函数，全部返回**新的 session 对象**、不修改入参 —— 这是「一次 `put()` 原子替换」能否成立的前提。

**拼写判定（D6）**
```ts
normalizeInput(x)            // trim + toLowerCase，仅此而已
judgeSpelling(input, answer) // 严格相等；不纠错、不近似
hasValidAnswer(word)         // /^[A-Za-z]+(?:['’-][A-Za-z]+)*$/ —— 脏数据 discombobulated[ 被挡住
```

**选词（D5/D6）**
```ts
selectWords({ entries, review_logs?, mode, count, rng?, now? })
  → { entries, dropped, available }
```
- `random`（复用 `lib/reviewQuiz.shuffle`，rng 可注入）/ `recent`（`added_at` 倒序）/ `wrong`（reviewLog 错误次数 + `in_wrong_pool`，错得多的在前）
- 英文无效 / 无释义 / 重复 `word_id` 全部被排除并**如实上报**（`dropped`），不静默丢弃
- 可用量不足时按实际数量返回（`available` 供 UI 提示）

**会话构造**：`createSessionDraft({...})` → 待持久化的单文档（不落库）

**状态机**（均返回 `{ session, result }`）
```ts
applyAttempt(session, { word_id, input, request_id, now? })
skipWord(session, { word_id, request_id, now? })
markUnavailable(session, { word_ids, reason, now? })   // 仅 PENDING/IN_PROGRESS 可转
markSrsReported(session, wordId, now?)                 // D2 防重复
pendingSrsWords(session)                               // 恢复后补交接用
```

**result 取值**：`correct` / `wrong` / `invalid` / `skipped` / `terminal`
**AttemptResult**：含 `consecutive_correct / target_correct / total_attempts / correct_attempts / wrong_attempts / word_status / next_word_id / session_status / progress / srs_due / at`，同时也是写入 `processed_requests[request_id]` 的回放值。

**会话生命周期 / 聚合**
```ts
pauseSession / resumeSession / abandonSession / isSessionStale / currentWord
sessionProgress / aggregateSession   // accuracy、completion_rate 分母为 0 时返回 null（渲染 "—"）
```

**两个实现判定请留意（我认为是该如此，若不合你意请指出）**：
1. **空白提交 = `invalid`，不计入任何计数**。方案原文没定义空白输入；按「误触回车不该把单词打回 0」处理，比「当成答错」温和，也不污染 `totalAttempts` 分母。
2. **PAUSED / ABANDONED 下提交易抛错**（调用方 bug，立刻暴露）；**SESSION_COMPLETED 下不抛**，直接返回 `terminal` —— 会话结束后用户又点一下属于正常交互，不该崩。

## 4. P0 覆盖对照（`scripts/test_spelling.ts`，127 项断言全绿）

| 方案 §九 P0 条目                    | 对应用例                                        |
| ------------------------------ | ------------------------------------------- |
| 初始连续正确次数为 0                    | `P0-1 初始状态`（同时校验 target=3 来自统一配置）           |
| 连续正确达到 targetCorrect 才完成       | `P0-2`（第 1/2 次仍在 IN_PROGRESS，第 3 次 COMPLETED） |
| 任意错误立即重置连续正确                   | `P0-3`（先连对 2 → 错一次归零 → 必须重新连对 3 次）           |
| 错误累计和总提交次数准确                   | `P0-4`（3 次错：total=3 / wrong=3 / correct=0）   |
| 正确率分母口径一致、跳过不进分母               | `P0-8`（4/6=67%，跳过没把分母变成 7）                  |
| 重复请求不重复计数                      | `P0-5`（同一 request_id 二次调用：计数不变、回放原结果、**返回同一个 session 引用**） |
| 已完成 / 跳过词条不能重复推进               | `P0-6`（完成后再提交 → terminal；重复 skip 回放；跳过的词不能再作答） |
| 写入失败不产生部分成功                    | `P0-7`（**状态机不修改入参** —— 这是单文档 put 原子性的前提）    |
| （新增）分母为 0 → null               | `P0-8b`（accuracy / completion_rate 为 null 而非 0%） |
| （新增）D6 拼写判定                    | 连字符严格（`baby sit` ≠ `baby-sit`、`babysit` ≠ `baby-sit`、`co-pilot` ≠ `copilot`）、大写不敏感（AIDS/aids）、脏数据不可作为答案 |
| （新增）D2 SRS 交接                  | 未达标的正确提交 srs_due=false；第 3 次对 srs_due=true；`markSrsReported` 后 `pendingSrsWords` 清空；重复标记幂等；**SKIPPED / 答错都不产生交接** |
| （新增）终态保护                       | 「失效词条」组：COMPLETED 词条即使出现在删除名单里也保持 COMPLETED；只转 PENDING / IN_PROGRESS；不可用数不重复累计 |
| （新增）选词模式与过滤                    | 三模式排序正确；脏数据 `invalid-word` / 无释义 `no-meaning` / 重复 `duplicate` 三类如实上报；请求量 > 可用量按实际数建会话 |
| （新增）生命周期                       | 暂停 / 恢复（清除 paused_at）/ 放弃 / 7 天过期判定（边界值 ±1ms）/ 自然收尾写 `ended_at` |

> 注：8 个「单词 + 中文释义」只作为**纯函数的测试输入**存在于 `scripts/test_spelling.ts`，与既有 `test_learning_loop.ts` 的做法一致：它们不进用户界面、不落库、不属于词库数据。**生产代码里没有任何硬编码词条。**
