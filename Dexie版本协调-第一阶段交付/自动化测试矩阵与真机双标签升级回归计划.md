## 3. 真机双标签升级回归计划

> 环境：puppeteer-core + Edge 双标签（端口 4174，严格 `strictPort`）；升级场景额外覆盖 Chromium + Firefox（V1.2.7 C6）。**本计划为设计态，不在本阶段执行。**

### 3.1 通用前置条件

1. 打包生产构建（v11→v12→v13→v14 迁移链已落地且经 C47–C65 自动化通过）。
2. 标签 A 进入某默写会话、持锁（`active_tab_id=A, lock_epoch=1`），已产生若干活动错词事件。
3. 标签 B 打开同会话（未持锁），用于触发接管 / 升级竞争。
4. 服务以 `npm run preview -- --port 4174 --strictPort` 启动（换端口 SW/Cache/IndexedDB 全作废）。

### 3.2 逐场景回归（前置 / 步骤 / 预期 / 失败判据）

| 场景 | 前置 | 步骤 | 预期 | 失败判据 |
| --- | --- | --- | --- | --- |
| **S1** T-A 已提交 T-B 未提交 + 升级 | A 已 `insertIfAbsent(E)`，凭证缺失 | 触发升级中断；升级完成重连 | drain 重放 T-B 恰一次；`cc=0`；错词本不漂移 | 永久 pending / 重复归零 |
| **S2** T-B 已提交 T-C 未提交 + 升级 | A 凭证已写、事件 `status` 落后 | 升级中断后重连 | 跳过 T-B、补 T-C；不重复归零 | 重复归零 / 重复错误提示 |
| **S3** `versionchange` 中断 in-flight | A 一笔事务 in-flight | 升级方触发 `versionchange` | 未确认事务按未提交；输入禁用 + 提示重输；不自动重放按键 | 静默丢失 / 假报继续 |
| **S4** 旧标签重开 ≠ 取得锁 | 锁已被 B 接管 | A 重新 `db.open()` 后试写 | `inputEnabled=false`；9 路径全拒；`myEpoch` 重读 | 沿用旧锁 / 漏锁写入 |
| **S5** 升级 blocked | 双标签均未释放连接 | 升级方 blocked | 页面只读、零写入、提示关闭其它标签 | 静默失败 / 假报完成 |
| **S6** 升级成功五步恢复 | 升级提交、数据原样 | 重连走五步链 | 五步缺一不可；恢复输入；数据一致 | 跳过取锁未被判失败 |
| **S7** 升级失败回滚 | 升级事务失败 | 旧版本页面重连 | 数据 = 升级前；重新校验版本与锁；不假报新版本 | 沿用旧锁 / 数据损坏 |
| **C64 叠加** 升级中途杀进程 | A/B 双标签 + 升级进行中 | 升级中途 `kill` 进程，再开标签触发重连 | 恢复链 + 升级流程叠加无数据丢失 / 死锁 | 任一中断点数据丢失 |

### 3.3 通过 / 失败汇总口径

- **通过**：上述每个场景「预期」全部成立，且「失败判据」所列异常均未出现；两条铁律（铁律 1 不声称 close 后事务继续、铁律 2 重开≠持锁）在断言中显式覆盖。
- **失败**：任一场景触发「失败判据」任一项；或 fake-indexeddb 自动化（C57–C64）未先通过即上真机。
