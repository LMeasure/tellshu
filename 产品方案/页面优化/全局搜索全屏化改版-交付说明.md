# 全局搜索全屏化改版 · 交付说明（2026-10-21）

> 输入：《阅读器排版与全局搜索组件修复：技术实现方案.md》（盲写方案）+ 用户 2026-10-21 四项裁决。
> 结论：**推翻此前的底部停靠面板 v2，改为全屏搜索层**；阅读器只做两处小收尾。
> 关联文档：《方案对照审查与实施手段-阅读器与全局搜索.md》（同目录）。

## 一、用户裁决（本次全部落地）

1. **推翻 V2，全屏 overlay**：入口行停靠在 Tab 栏上方，点一下展开全屏搜索层；
2. **聚焦绿框去掉，只保留光标**：文本输入框显式豁免全局 `*:focus-visible` 焦点环；
3. **滚动条一律隐藏**：阅读器上下滚动模式也不再显示滚动条（保留滚动能力）；
4. **不要「查看全部」入口**：点结果跳详情、回车去全页搜索。

## 二、改动清单

### 1. 搜索历史改为「访问记录」模型（核心规则）

`src/store/useAppStore.ts`：
- `searchHistory: string[]` → `SearchHistoryItem[]`（`{ query, count, lastAt }`，新→旧）；
- `addSearchQuery` → **`recordSearchVisit`**：小写去重、`count+1`、刷新 `lastAt`、置顶、超 `MAX_SEARCH_HISTORY(10)` 丢最旧；
- persist `merge` 增加 `normalizeSearchHistory`：旧存档（string[]「查询词」模型）迁移成 `count:1` 的访问记录，升级用户不丢数据、不出类型错误。

### 2. SearchDock 重写为全屏搜索层

`src/components/layout/SearchDock.tsx`（整文件重写）：
- **入口行**（收起态）：搜索图标 + 「搜单词…」（点开全屏层）+ 语音输入（点开层并开始识别）+ 扫描识别（跳 `/import?tab=scan`）；
- **全屏层**：`createPortal` 到 `document.body`（避开入口行 `backdrop-blur` 的 containing block，层级高于 Tab 栏 z-30 与同步角标），`fixed` 全屏，`bottom: var(--kb-inset, 0px)` —— 键盘弹起时层底贴在键盘上沿；
- **历史写入规则（极其重要，已按裁决实现）**：`recordSearchVisit(h.word)` **只出现在「点击搜索结果 → 跳 /word/:word」的 onClick 里**；打字、回车去全页、点历史重搜，都不写历史；
- **历史展示**：无输入时显示；时间倒序（最近点击在最上面，store 新→旧直接渲染、不反序）；重复访问同一词显示 `×N` 角标（仅 >1 显示）；「清空」按钮一键清空；空历史给引导文案；
- **结果排序与贴底**：最高匹配固定在最下方紧贴输入框；CSS `justify-end + min-h-full` 贴底 + 变化后 `scrollTop = scrollHeight` 滚底双保险；
- **IME 防误触**：Enter 时判 `e.nativeEvent.isComposing || e.keyCode === 229`，组词期回车只确认候选词；
- **空态**：统一「该词暂未收录」（与 `/search`、`/word/:word` 全站一致）；
- **无「查看全部」入口**；
- **聚焦无环**：输入框 `outline-none ring-0 ring-offset-0 focus-visible:ring-0 focus-visible:ring-offset-0`，只保留光标；
- **收起**：Esc / 顶栏「收起搜索」/ 点结果跳转 / 路由变化；
- 保留：300ms 防抖（空串立即生效）、竞态序号、语音 partial 回填、`PANEL_LIMIT=30`。

### 3. 阅读器与样式收尾

- `src/index.css`：`.reader-scroll` 由「细绿滚动条」改为**隐藏**（一律隐藏，含上下滚动模式）；新增 `.scrollbar-hidden` 工具类（搜索列表复用）；
- `src/pages/Reader.tsx`：上下滚动模式正文 `pb-8 → pb-14`、记忆模式滚动区 `py-4 → pt-4 pb-14`，底部留白补足到导航栏总高 56px（`h-14` + `safe-bottom` 在 border-box 下恰 56px），末行不再被呼出的导航栏盖住；
- `src/hooks/useKeyboardInset.ts`：visualViewport 主路径补 `KEYBOARD_MIN_PX = 120` 阈值（与降级路径一致），防 iOS 地址栏收缩 / 页面滚动导致停靠组与搜索层抖动。

### 4. 测试

`scripts/test_word_detail.ts`：dock/store 断言整体更新到新设计（全屏层 + Portal、isComposing、该词暂未收录、贴底、recordSearchVisit 唯一写入点、历史不反序、×N 角标、ring-0、访问记录模型、旧存档迁移、键盘阈值、scrollbar-hidden、reader pb-14）。

## 四、诚实边界（未验证 / 已知限制）

1. **iOS Safari 程序化 focus 不弹软键盘**：全屏层展开时自动聚焦输入框，桌面/Android 可直接唤起键盘；iOS 需用户再点一下输入框（平台限制，无可靠绕法，已在代码注释标明）。
2. **语音识别无法中途停止**：`speechService.cancel()` 只停语音合成、停不了识别实例（既有能力边界，本次未扩）；层收起后识别仍在跑，partial 继续回填输入框。
3. **像素级未覆盖**：jsdom 无布局引擎，贴底对齐、键盘避让、滚动隐藏、末行避让导航栏均需真机验证（iOS Safari / Android Chrome / PWA 独立窗口）。
4. **键盘阈值 120px 是防御性修复**：本机无 iOS 设备，无法实测地址栏抖动是否真实存在；主路径加阈值与降级路径对齐，真机表现待验证。

## 五、方案对照中的一处更正（证据纪律）

审查报告曾把「分页不按整行切」列为阅读器核心缺口（G1）。实施前复核 `fitPaging.ts` + `Reader.tsx` 测量链路后确认：**探针与正文渲染完全同构**（`splitSentences().join(' ')` + 句间空格），`heightOf(para, start, end)` 随 `end` 单调阶梯变化（行内增减字符不改变高度），二分得到的「最大可容 end」天然落在行盒边界上；`lastBreak` 对中文是无操作。**现有分页已经是整行切分，G1 不成立，本次未改 `fitPaging.ts`。** 方案模块一的「吃字」根因假设（未扣导航栏高度）也早已由 `NAV_RESERVE=56` 解决。阅读器侧只剩上述第 3 节的三处小收尾。

## 六、遗留与后续建议

- 真机验收清单（建议用户在手机/PWA 上过一遍）：全屏层开合、键盘弹起时输入框贴键盘、短结果集贴底、历史 ×N 角标、组词期回车、上下滚动模式末行避让导航栏、滚动条隐藏。
- 入口行的语音/扫描从「直接可用」变为「点开层后可用/扫描直接跳转」：语音需多一次点按（开层），扫描不变。若想恢复一键语音，可在后续迭代把入口行麦克风改为「开层 + 立即识别」（当前已实现该行为，仅多一次开层的视觉过渡）。
