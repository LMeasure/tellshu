# 述树单词默写 V2：交互改版与错词本

## 一、任务目标

以用户提供的 Qwerty Learner 截图为视觉参考，改造现有「单词默写」页面。

本轮重点：

1. PC 与手机端自适应。
2. 单词本身就是输入区域，取消独立输入框。
3. 输入正确字母实时变色，完整正确后自动切换下一个单词。
4. 支持显示/隐藏单词。
5. 支持组合快捷键播放发音和切换显示状态。
6. 建立错词本功能，支持错词记录与再次练习。

**本轮是现有功能改造，不是重新开发单词默写系统。**

## 三、单词直接输入交互

### 3.1 核心界面

取消原有独立拼写输入框和提交按钮。

用户直接在中央单词区域输入字母。

以 `horsepower` 为例：

- 初始：`horsepower` 全部显示。
- 用户输入 `h`：`h` 变绿，其余字母保持原色。
- 输入 `hor`：`hor` 变绿，其余字母保持原色。
- 完整输入正确：自动完成当前答题并切换下一个单词。

显示状态：

- 已正确输入的字母：绿色。
- 尚未输入的字母：深灰色。
- 当前输入错误：红色反馈。
- 支持 Backspace 删除，恢复对应字母的待输入状态。

输入焦点应由单词区域的交互层管理，不再显示传统输入框边框。

### 3.2 错误处理

用户直接在单词区域输入。

正确字母立即变绿，并自动进入下一个字母。

错误字母立即显示红色反馈，同时播放一次错误提示音。

错误字母不写入答案，不推进输入位置。

红色反馈短暂显示后自动恢复原色。

用户无需退格、无需重新输入前面正确的字母，只需重新输入当前应输入的字母。

错误时连续正确次数归零。

错误事件不得因重复渲染或重复事件被重复记录。

错误提示音不得连续叠加播放，应设置合理的防抖或播放保护。

手机端和 PC 端保持一致的错误反馈逻辑。

注意区分：

错误按键：即时红色反馈、提示音、停留在当前字母。

错误记录：按现有答题状态机和错词本规则处理，不得把一次错误按键误算成多次完整答题。

正确完成：仍按连续正确 3 次的原规则完成单词并交接 SRS。

### 3.3 连续正确规则

继续遵守原有规则：

- 每个单词连续正确 3 次才完成。
- 错误立即将连续正确次数归零。
- 不改变目标正确次数。
- 达到 3 次后标记 `COMPLETED`。
- 只有完成状态才执行既定 SRS 交接。
- 完成反馈短暂显示后自动切换下一个单词。

不得修改原有答题状态机和 SRS 语义来适配 UI。

## 四、显示 / 隐藏单词

在中央单词区域附近提供眼睛图标。

支持两种模式：

**显示模式**

- 显示完整单词。
- 已正确输入的字母绿色。
- 未输入字母保持深灰色。

**隐藏模式**

- 未输入的字母使用下划线占位。
- 已正确输入的字母仍显示绿色。
- 不得通过 DOM、无障碍标签或其他视觉提示泄露完整答案。
- 临时显示单词不会计入答题，不改变连续正确次数。

切换显示状态不能：

- 重建当前会话；
- 改变当前单词；
- 重置输入进度；
- 重复记录答题；
- 触发 SRS。

显示模式应持久化为用户练习偏好；恢复会话时保留设置。

## 五、PC 端快捷键

实现以下组合快捷键：

| 快捷键            | 功能         |
| -------------- | ---------- |
| 同时按住 Space + G | 播放当前单词发音一次 |
| 同时按住 Space + H | 切换单词显示/隐藏  |

具体要求：

1. Space + G 必须是一次组合操作，只播放一次。
2. 持续按住组合键不能连续播放。
3. 必须释放组合键后才能再次触发。
4. Space + H 每次组合操作只切换一次。
5. 不允许 Space 触发页面滚动。
6. 不允许快捷键误触发浏览器默认操作。
7. 在非练习页面不注册这些快捷键。
8. 输入法组合输入期间不触发快捷键。
9. 处理 keydown、keyup、重复事件和窗口失焦，避免按键状态残留。
10. 输入焦点位于练习区域时正常工作；其他输入控件中不得误触发。
11. 页面暂停或练习结束后，快捷键停止执行。

建议使用明确的按键状态管理，不要仅依靠 `event.key` 的单次判断。

## 六、手机端适配

手机没有实体键盘，因此不能依赖快捷键。

在单词区域提供两个容易点击的图标：

- 发音按钮：播放当前单词一次。
- 眼睛按钮：显示/隐藏单词。

要求：

- 点击区域足够大，建议至少 44×44 CSS px。
- 不遮挡单词和输入反馈。
- 虚拟键盘弹出时页面不能错位。
- 输入时不出现横向滚动。
- 适配 360px、375px、390px、430px 宽度。
- PC 端适配 1024px、1280px、1440px、1920px。
- 使用现有 `lg(1024px)` 断点策略；不要擅自增加断点。
- 手机端保持原有导航及页面行为，不因 PC 改造而改变。

特别验证 iOS、Android 虚拟键盘下的输入焦点、退格、自动切词行为。

## 七、错词本功能

错词本是本轮新增的独立功能。

### 7.1 记录规则

当用户完成一次错误拼写时：

- 将对应单词加入错词本。
- 保存错误次数。
- 保存最近错误时间。
- 保存正确答案及必要的词汇关联信息。
- 同一个单词应合并记录，不要重复创建多个重复词条。
- 后续再次答错，更新错误次数和最近错误时间。
- 后续掌握该单词时，按明确的状态规则更新错词记录。

不要将单个错误按键、退格修正或尚未完成的输入记入错词本。

### 7.2 错词本页面

先检查现有词汇管理和生词本页面，优先复用现有组件与数据访问层。

错词本至少提供：

- 错词列表。
- 单词及音标。
- 中文释义。
- 错误次数。
- 最近错误时间。
- 单词发音。
- 再次练习入口。
- 移除错词记录的操作。

列表支持合理的排序，优先展示最近错误或错误次数较多的单词。

### 7.3 错词再次练习

支持从错词本选择单词进行专项默写。

要求：

- 使用现有单词默写状态机。
- 仍然执行连续正确 3 次（次数可以设置）的规则。
- 答题结果继续持久化。
- 不因进入错词本练习而重复创建同一错词记录。
- 不破坏原有练习会话。
- 错词本练习与普通练习的来源应能区分。

### 7.4 与 SRS 的关系

错词本是错误记录和专项练习入口，不替代 SRS。

遵循现有规则：

- 错误使连续正确次数归零。
- 错误不增加目标正确次数。
- 本轮完成后的下次复习由既有生词本机制独立安排。
- 只有 `COMPLETED` 才执行既定 SRS 交接。
- `SKIPPED`、`UNAVAILABLE` 不执行 SRS 交接。

不得为了错词本直接修改 `recordQuiz` 的既有语义。

### 7.5 幂等与数据安全

- 同一错误事件不能重复计数。
- 使用现有 `request_id` 幂等机制。
- 不允许 UI 重渲染导致重复写入。
- 不删除或覆盖现有词汇数据。
- 先确认现有 Dexie 表和索引，再决定是否需要迁移。
- 如果需要数据库版本升级，必须独立评审迁移方案和旧数据兼容性。

## 八、视觉设计要求

参考用户提供的 Qwerty Learner：

- 极浅灰紫背景。
- 中央单词大字号显示。
- 正确字母绿色。
- 未输入字母深灰色。
- 音标位于单词下方。
- 中文释义居中显示。
- 发音和眼睛图标放在单词附近。
- 顶部显示进度条、题目数量、暂停。
- 底部展示时间、正确数、正确率等实时统计。
- 白色圆角卡片、轻阴影、适度留白。

不要照搬截图中的品牌、Logo 或版权素材。

PC 端充分利用屏幕空间；手机端采用纵向布局，保证单词区始终处于视觉中心。
