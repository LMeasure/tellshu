## 3. 完整数据库 ER 设计（推荐方案）

> 原则：**公共表不动结构（仅加兼容列），私有表独立新建**，避免污染公共 HNSW 索引与召回率。所有新增为**可加列 / 可加表**，不删不改历史列。

### 3.1 逻辑实体 → 物理表
- **Work** → `book_works`（新）
- **Edition** → `book_editions`（新，`source_site`+`source_id` 落此层，`legacy_book_id` 保留 BIGSERIAL 回溯）
- **Content Version** → `book_content_versions`（新）
- 章节/分块/向量 → `discovered_book_chunks`（扩展：加 `content_version_id`、`section_type`、`owner_id NULL`）
- 用户私有书 → `user_books` + `user_book_chunks`（新，独立表 + 独立 HNSW）
- 书架关系 → `user_bookshelf`（新）
- 知识库 → `knowledge_bases` + `kb_books`（新）
- 身份镜像（可选）→ `app_users`（新，`user_id` = Supabase `sub`）

### 3.2 ER 关系
```
book_works(1)──<(N)book_editions(1)──<(N)book_content_versions(1)──<(N)discovered_book_chunks
                                                       │
                          user_books(owner_id) ──< user_book_chunks(owner_id)
                          user_bookshelf(owner_id) ── 关联 work/edition/book（仅关系）
                          knowledge_bases(owner_id) ──< kb_books(owner_id) ── 关联 public/user book（仅关系）
                          app_users(user_id=sub) ── 镜像 Supabase Auth
```
- `discovered_book_chunks.book_id` 现有 FK → `discovered_books.id ON DELETE CASCADE` **保留**（公共书仍用 `book_id` 兼容；`content_version_id` 为冗余映射列，便于统一查询）。
- 私有表 `user_book_chunks` 的 HNSW 独立建索引；公共表 HNSW 索引**不动**。

## 4. 表结构与字段定义（推荐方案）

### 4.1 新增 / 扩展表（DDL 草案，实施前需 spike 复核类型）
```sql
-- 兼容列（加到现有表，不改历史列）
ALTER TABLE discovered_books
  ADD COLUMN work_id uuid,
  ADD COLUMN edition_id uuid;
ALTER TABLE discovered_book_chunks
  ADD COLUMN content_version_id uuid,
  ADD COLUMN section_type text NOT NULL DEFAULT 'body',  -- body|title_page|copyright|toc|preface|transcriber_note|illustration
  ADD COLUMN owner_id uuid;  -- NULL=公共

-- 新逻辑表
CREATE TABLE book_works (
  work_id uuid PK DEFAULT gen_random_uuid(), canonical_title text, original_title text,
  author text, original_lang text, description text,
  merge_key text, merge_status text DEFAULT 'auto', merged_into uuid);
CREATE TABLE book_editions (
  edition_id uuid PK DEFAULT gen_random_uuid(), work_id uuid FK→book_works,
  language text, translator text, publisher text, publish_year int, edition_note text,
  is_abridged bool, format text, isbn text,
  source_site text, source_id text, legacy_book_id bigint);  -- 保留 BIGSERIAL
CREATE TABLE book_content_versions (
  content_version_id uuid PK DEFAULT gen_random_uuid(), edition_id uuid FK→book_editions,
  source_file_ref text, normalized_content_ref text, content_sha256 text,
  parser_version text, parsed_at timestamptz, chapter_schema_version text,
  chunk_strategy_version text, embedding_model text, embedding_version int,
  index_status text, owner_id uuid NULL);
-- 私有书
CREATE TABLE user_books (
  user_book_id uuid PK, owner_id uuid NOT NULL, work_id uuid NULL, edition_id uuid NULL,
  content_version_id uuid NULL, original_file_ref text, status text, created_at timestamptz DEFAULT now());
CREATE TABLE user_book_chunks (
  id bigint PK, user_book_id uuid FK→user_books ON DELETE CASCADE, chunk_index int,
  chapter_title text, chapter_number int, content text NOT NULL, content_chars int NOT NULL,
  embedding vector(1024), embedding_model text DEFAULT 'BAAI/bge-m3',
  embedding_dim int DEFAULT 1024, embedding_recipe text DEFAULT 'v1-book-chapter',
  section_type text DEFAULT 'body', owner_id uuid NOT NULL);
CREATE INDEX ... USING hnsw(user_book_chunks.embedding vector_cosine_ops);
-- 关系
CREATE TABLE user_bookshelf (id uuid PK, owner_id uuid, target_type text, target_id text, created_at timestamptz);
CREATE TABLE knowledge_bases (kb_id uuid PK, owner_id uuid, name text, scope text, created_at timestamptz);
CREATE TABLE kb_books (kb_id uuid FK, owner_id uuid, book_ref_type text, book_ref_id text, added_at timestamptz);
```

## 7. Supabase Auth 接入设计（推荐 B1）

### 7.1 方案要点（红线 #7 合规）
- **Supabase Auth 负责真实账号**（邮箱+密码、邮箱验证、密码重置、会话刷新、OAuth）。
- **Supabase 密钥只存服务端** `api/.env`（类比 `server/.env` 红线）：`SUPABASE_URL`、`SUPABASE_ANON_KEY`、`SUPABASE_JWT_SECRET`。**前端不嵌入任何令牌**（与前提卡红线 #7 一致）。
- **Auth 经后端代理**：前端调 `POST /api/auth/login`（FastAPI），后端用 `SUPABASE_ANON_KEY`（服务端）调用 Supabase Auth `/token`，**前端永不接触 anon key**；后端把 Supabase JWT 回传，前端存 Dexie `session`（非 localStorage，沿用现有桩模式）。
- 替换 `auth/web.ts`：从本地 uuid 桩 → 调 `/api/auth/*`；替换 `sync/remote.ts` 的 `LocalSyncStub` → 真实 `RemoteSyncClient`（Supabase Postgres 或现有 PG）。

### 7.2 接入步骤
1. 创建 Supabase 项目（用户授权后），拿到 URL/anon/JWT secret。
2. `api/.env` 加上述密钥（不提交、不贴聊天）。
3. FastAPI 加 `auth` 路由（register/login/logout/refresh/`me`）。
4. 前端 `authService` 改调后端；`StartLogin`/`Profile` 页接 Supabase 登录 UI（经后端）。
5. 首次登录回写 `app_users`（镜像 `sub`/email）。

## 8. JWT / GUC / RLS 安全设计

### 8.1 JWT 验证（FastAPI 中间件）
- 每个需鉴权的请求：`Authorization: Bearer <JWT>` → 用 `SUPABASE_JWT_SECRET` 服务端验签（不信任客户端 `owner_id`）→ 取 `sub`。
- 公共检索（`/api/discover`）**不加**鉴权（保持现状）；私有/书架/知识库/上传接口**强制**验 JWT。

### 8.2 会话级用户上下文（GUC，自托管 PG 等价 `auth.uid()`）
```sql
CREATE OR REPLACE FUNCTION current_user_id() RETURNS uuid LANGUAGE sql STABLE
AS $$ SELECT nullif(current_setting('app.current_user_id', true), '')::uuid $$;
```
- 每个请求在**事务内**执行 `SET LOCAL app.current_user_id = '<sub>'`（`api/db.py:88-89` 的 `set_config(..., true)` 同款，连接归还即清空）。
- 私有表策略：`ALTER TABLE user_book_chunks ENABLE ROW LEVEL SECURITY; CREATE POLICY own ON user_book_chunks USING (owner_id = current_user_id());`（同理 `user_books`/`user_bookshelf`/`knowledge_bases`/`kb_books`）。

### 8.3 连接池安全（用户重点关注，必须验证）
- 【事实】`api/db.py` 用 `ThreadedConnectionPool`，每连接 init 语句含 GUC（`ef_search=800` 等）。
- 【推荐】鉴权请求在事务开头 `SET LOCAL`（**非 `SET`**），事务提交/回滚后 GUC 自动丢弃；连接归还连接池后**不会泄漏**上一用户的 `sub`。
- 【必须测试】连接复用泄漏用例：连续两个不同用户请求复用同一连接，断言第二个请求读到的 `current_user_id()` 是自己的 `sub`，不是上一个。
- 【禁止】绝不信任客户端传入 `owner_id`；`owner_id` 一律由中间件从 JWT `sub` 写入。

### 8.4 跨用户越权测试（设计，实施时落地）
1. 用户 A 用 book_id 猜用户 B 私有书 → 404（不泄露存在性）。
2. 请求带 B 的 `owner_id` 参数 → 服务端忽略，强制用 JWT `sub`。
3. A 请求 B 私有书文件签名 URL → 401。
4. A 读 B 对话引用 → 403。
5. 删用户 → 级联清理其私有书/知识库/对话；公共书不受影响。

## 9. Dexie v11 → v12 迁移设计（本地数据保护）

- **v12 仅新增索引，不改历史版本**（`storage/web.ts:6` 铁律）：
  `this.version(12).stores({ readings: 'id, created_at, type, on_shelf, owner', annotations: 'id, doc_id, created_at, owner' })`
- `owner` 列 = Supabase `sub`（NULL = 仅本地，不上云）。**现有本地数据不自动上传、不清空**（`owner` 默认 NULL）。
- **迁移失败恢复**：Dexie 把 schema version ×10 写进原生 IDB（v12→IDB v120）；存量库升级夹具必须**先建 version 110（补齐全部 v11 表与索引）**再 v120，否则 Dexie 从 v1 重放会重建/丢表（已踩坑，见工作区记忆）。
- 上传时 `owner` 仅在用户**主动选择**后写入；失败不影响本地原数据；保留 `readings.id` 兼容映射。

## 10. 六本书章节识别修复方案

### 10.1 根因（事实）
- `ingest-books.py:313-340 build_chapter_anchors`：`chapters` 为 null/空 → 返回空列表 → 全部分块 `chapter_title=NULL`。
- crawler `crawl-books.ts:1191 parseChapters` + 正则集（`:126-143`）对这 6 本书**未识别**章节（非标准标题 / `tocFromRdf` 为 null）。

### 10.2 兜底方案（推荐，零向量重建）
- 新增 `scripts/repair-chapters.py`（只读原 chunks，UPDATE 元数据）：
  1. 对 6 个 `book_id`，`SELECT content, chunk_index, content_chars FROM discovered_book_chunks WHERE book_id=? ORDER BY chunk_index` → 拼接全文。
  2. 用**更宽的章节正则**（支持 `CHAPTER`/`BOOK`/`ACT`/`SCENE` + 罗马/阿拉伯/单词数字 + 可选标题）在全文检测章节起点。
  3. 按累计字符偏移把每个 chunk 映射到章节 → `UPDATE chapter_title/chapter_number`（按 chunk_index 主键），并置 `section_type='body'`。
- **不重建向量**（`chapter_title` 与 `embedding` 是独立列）；幂等（可重算）、可逆（回填 NULL 即还原）。
- **441 paratext 块**：另写标记脚本，按内容启发式（`[Illustration]`、目录行、`Transcriber's Note`、版权页特征）置 `section_type`，**保持 `chapter_title IS NULL`、保持检索过滤行为不变**。

### 10.3 边界核验
- 修复后重跑评测：确认 6 本书在各自正常查询下进入召回（它们不在 31 条未命中集，但应验证其常规检索恢复）。
- 章节边界抽样人工核对（避免正文内 "Chapter" 误判）。

## 11. BM25 混合检索方案（Reranker 之前）

### 11.1 顺序（V1.1 实证结论）
1. ✅ 修 6 本书（§10，零算法）。
2. **扩候选池**：检索 `LIMIT` 30→50（向量）+ BM25 候选。
3. **BM25**：优先评估 PostgreSQL `tsvector` 生成列 + `to_tsquery`/`websearch_to_tsquery` + `ts_rank`（与现有 PG 同源，零额外服务）。
4. 融合：向量 Top-K ∪ BM25 Top-K → RRF（Reciprocal Rank Fusion）或加权 → 取 Top-50。
5. 复测 Recall@10/@50；残余未命中集分布决定**是否**引入 Reranker（bge-reranker-v2-m3，与 bge-m3 同生态）。

### 11.2 关注项
- HNSW 过滤后召回率（扩池后实测 P50/P95）。
- 私有书 BM25：`user_book_chunks` 建 `tsvector` 生成列 + 同款融合；按用户可见 book 集合 `id = ANY(ARRAY[...])` 过滤，避免大表 `owner_id` 过滤退化。
- 公共/私有混合检索（知识库「整库」范围）= 公共候选 ∪ 用户私有候选 → 融合。
- 【待验证】`tsvector` vs `pg_search`（ParadeDB）的召回/延迟/运维成本，先 spike 再定。

## 13. Worker 任务设计

- **用户上传管线**（类比 ASR sidecar 模式，`server/asr_service/`）：文件落对象存储 → Python Worker 解析正文 → 分块 → 嵌入（复用 `ingest-books.py` Embedder）→ 写 `user_book_chunks`（带 `owner_id`）→ 更新 `user_books.status` → 可选自动加知识库。
- Worker **显式携带 `owner_id`**（不依赖会话 GUC）；按 `content_sha256` 幂等（重复上传识别）。
- 失败重试 / 取消 / 进度回调；失败不影响原本地 Dexie 数据。
