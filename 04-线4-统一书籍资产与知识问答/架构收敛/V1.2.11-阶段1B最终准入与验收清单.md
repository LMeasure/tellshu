## §〇 本文在 V1.2.11 体系中的位置

V1.2.11 的目标是把 V1.2.8→V1.2.10 的历史决策冲突收敛为一份「可准入、可验收、可回滚」的终稿。前序三件交付物分别解决了：

| 交付物 | 解决的核心问题 |
|---|---|
| 架构收敛稿 | 消除历史文档冲突（C-1~C-8），定稿数据模型（含 ER/数据流）、配额原子 SQL、幂等九步、认证 RLS、Dexie v12/v13、免费开放体系 |
| D1–D7 及 Q21–Q28 负责人决策稿 | 把每个待裁定项拆成 9 字段矩阵（现状事实/历史设计/风险/建议/成本/依赖/验收/回滚/待裁定），明确「建议≠批准」 |
| Cloudflare R2 接入架构设计 | R2 存储分级（≥6 类）、适配器接口、安全边界、成本模型（不编数字）、词典 410MB 接缝不动 |

本文在此基础上，把这些方案映射为 **12 项准入门禁**，并区分 **5 个就绪状态阶段**，使「什么已经设计好、什么还有待负责人拍板、什么还一行代码没动」一目了然。

## §一 五个就绪状态阶段的定义

为避免「文档写完了就当系统做好了」的误判，统一使用以下五阶段。任何门禁只能标注为其实际达到的最高阶段，不得跳级。

| 阶段代号 | 阶段名称 | 判定标准（必须满足全部） |
|---|---|---|
| **P1** | 架构设计完成 | 方案已在 V1.2.11 文档中定稿，接口/SQL/流程图齐备，无内部矛盾 |
| **P2** | 负责人决策完成 | 该门禁涉及的 D1–D7 / Q15–Q28 待裁定项已由负责人书面批准（含否决/改判），决策稿中「待裁定」已闭合 |
| **P3** | 技术预演完成 | 在临时库/隔离环境按《临时库十步预演》跑通关键路径（如复合外键、配额并发、RLS 生效），有可复现证据 |
| **P4** | 实际实施完成 | 在生产等价环境落地对应 DDL/代码/配置，并通过集成测试，无遗留 TODO |
| **P5** | 生产验收完成 | 生产环境运行 ≥ 观察期（建议 7×24 灰度），监控/备份/回滚均验证过，可正式放量 |

> ⚠️ **红线**：P1 不能充作 P4；文档定稿不能当作实施完成。本文所有门禁的「当前最高阶段」均如实标注，未授权前一律不超过 P1/P2。

## §三 逐项门禁详述

### G1 — 数据库四角色完成整改
- **目标**：建立 `shutree_app` / `shutree_api` / `shutree_worker` / `shutree_migrator` 四个最小权限角色，废止共用超级权限账户直接连库。
- **验收证据**：`\du` 显示四角色存在且 `NOSUPERUSER` / `NOBYPASSRLS`；各角色仅持有其职责所需权限；连接串按服务切换角色。
- **当前状态**：P1。架构收敛稿 §六已定义四角色职责矩阵；Git 基线中尚未创建任何角色（红线禁止本轮创建）。
- **风险**：角色权限过宽 → 越权；过窄 → 功能不可用。须由 DBA 按收敛稿矩阵落地。
- **回滚**：保留旧连接账户只读权限直至新角色验证通过；可一键切回。

### G2 — 运行期非 postgres 超管
- **目标**：运行期应用连接**绝不**使用 postgres 超级用户；GUC `app.current_user_id` 仅作 RLS 上下文，**不是认证机制**。
- **验收证据**：生产连接串角色 ≠ postgres；应用启动后 `SHOW app.current_user_id` 可被会话级 SET，但无 SUPERUSER 能力。
- **当前状态**：P1。决策稿 D3/Q22 已明确禁止运行期超管；代码层 `server/` 当前连接配置待核实（需负责人授权后查 `.env` 占位，非本轮）。
- **风险**：误用超管 → 一行 DDL 击穿全部 RLS。
- **回滚**：连接角色配置回退至既有专用角色。

### G3 — RLS 生效（ENABLE 非 FORCE）
- **目标**：在用户表/私有书表/资源表上 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`；**推荐 ENABLE 而非 FORCE**（FORCE 会强制表所有者也受控，易误伤迁移/运维脚本，详见决策稿 D3/Q23 论证）。
- **验收证据**：`SELECT relname FROM pg_class WHERE relrowsecurity` 命中目标表；以普通用户角色查询他人行返回空；以 migrator 角色（BYPASSRLS）可运维。
- **当前状态**：P1。收敛稿 §六给出 RLS 策略模板与矩阵；未执行。
- **风险**：漏开 RLS → 跨用户数据泄露；FORCE 误用 → 迁移脚本失效。
- **回滚**：`DISABLE ROW LEVEL SECURITY` 即时回退（仅限紧急）。

### G4 — 真实身份认证接入
- **目标**：接入 Supabase Auth（B1 方案，仅 Auth，不迁移自托管 PG）签发 JWT；应用侧校验 `sub` 作为 `owner_id` 来源，取代前端 `auth/web.ts` 的本地随机 `uuid()` stub。
- **验收证据**：登录后前端拿到真实 JWT；后端中间件校验签名与过期；`owner_id` 来自 JWT `sub` 而非本地生成。
- **当前状态**：P1。收敛稿 §六、决策稿 D4/Q24 已定方案；Git 基线前端仍为 stub（红线禁止改动）。
- **风险**：JWT 校验缺失 → 伪造身份；Auth 供应商绑定过深 → 迁移成本。
- **回滚**：保留 stub 作为离线兜底；Auth 故障切换到本地 guest（须明确 guest 不跨设备同步）。

### G5 — 复合外键 + 资源治理表 SQL 定稿
- **目标**：① 公有/私有书物理分离，私有表带 `owner_id uuid NOT NULL`；② 跨用户隔离用**双列 NOT NULL 复合外键**（关闭 MATCH SIMPLE 旁路）；③ 资源治理表（`resource_usage` / `quota_limit` / `idem_key` 预留）SQL 定稿。
- **验收证据**：DDL 脚本可幂等执行；复合外键 `(\owner_id, book_id)` 拒绝 NULL 任一列；级联删除规则符合收敛稿 §三（私有书删除级联清理其 chunks/annotations）。
- **当前状态**：P1。收敛稿 §三/§四/§五给出完整 SQL 草案与 ER 图；**`__public__` 虚拟用户已被正式废止**（覆盖 V1.2.8 D2 的 TEXT+sentinel 旧建议），见 C-1 冲突消解。
- **风险**：复合外键遗漏 NULL 防护 → 隔离失效；级联误配 → 误删。
- **回滚**：DDL 置于可回滚迁移事务；`DROP TABLE` 前全量备份。

### G6 — Dexie v12/v13 离线路径升级
- **目标**：Dexie 由 v11 前向升级至 v12/v13（原生 IDB version = n×10）；新增 `owner` 列默认 `'guest'`；注册 `db.on('blocked')` 与 `db.on('versionchange')`；**保持纯离线主学习链路不变**。
- **验收证据**：升级后已有数据无丢失；多标签页 versionchange 不卡死；离线导入/阅读主链路回归通过。
- **当前状态**：P1。收敛稿 §七给出升级步骤与事件处理；Git 基线为 v11，5 张表无 owner（红线禁止改动）。
- **风险**：前向升级不可逆；旧客户端未更新 → blocked 事件；owner 默认值错误 → 串号。
- **回滚**：IDB 升级在独立迁移函数内，异常捕获后回退到旧 version 读取；保留 v11 构建产物。

### G7 — 配额服务 + 幂等结算
- **目标**：① 配额「先判后增」原子 SQL（见收敛稿 §四）；② 幂等键 `idem_key` + 预约-结算模型（计数型/容量型/令牌型三类资源）；③ 9 步生命周期（收敛稿 §五时序图）。
- **验收证据**：10 配额 / 11 并发压测下无超额（用收敛稿 §四的并发测试脚本）；同一 `idem_key` 重复提交只结算一次；死信/重试可观测。
- **当前状态**：P1。SQL 与九步时序已拟；未实施。
- **风险**：非原子判增 → 超额发放；幂等键缺失 → 重复扣减；AI Token 免费期观察策略误当结算（决策稿明确免费期仅观测不扣）。
- **回滚**：配额表独立，回滚仅需停配额服务并切 guest 无限额度（临时）。

### G8 — 备份恢复演练
- **目标**：建立 PG 逻辑/物理备份策略 + 定期恢复演练；R2 对象版本化/生命周期规则。
- **验收证据**：最近一次恢复演练 RTO/RPO 达标；演练记录可查；恢复后数据一致性校验通过。
- **当前状态**：P0/未启动（仅原则，无专属脚本）。**必须在 G9 之前具备基础备份能力。**
- **风险**：无演练 → 真实故障不可恢复；R2 无版本化 → 误删不可回。
- **回滚**：N/A（本身即兜底能力）。

### G9 — 临时库十步预演
- **目标**：在临时库按规划脚本跑通 G1–G7 关键路径（四角色、RLS、复合外键、配额并发、幂等、Dexie 升级模拟）。
- **验收证据**：十步脚本输出日志齐全；每步断言通过；问题清单闭合或升级为门禁阻塞项。
- **当前状态**：P1。步骤与脚本框架已在收敛稿/决策稿隐含；未执行。
- **风险**：跳步 → 生产暴露设计缺陷；临时库与产线版本漂移。
- **回滚**：临时库可整体销毁重建。

### G10 — R2 接入 + 安全边界
- **目标**：① 词典 410MB **不改数据、不改前端**，仅切换 `VITE_DATA_BASE_URL` 指向 R2 public bucket；② 私有用户存储走 `shushu-private` + 预签名 URL；③ 七条安全边界（见 R2 设计稿 §三）。
- **验收证据**：前端经新 base URL 拉到词典；私有对象无公网裸链；预签名 URL 逾期失效；密钥仅服务端 `.env`。
- **当前状态**：P1。R2 设计稿已定接口/分级/边界；**R2 账户未注册、未配置、未上传**（红线禁止本轮）。
- **风险**：410MB 误迁移 → 带宽/一致性风险（设计稿明确禁止）；公网裸链 → 泄露；密钥泄露 → 对象遍历。
- **回滚**：`VITE_DATA_BASE_URL` 回指原存储；私有 bucket 策略收紧。

### G11 — 用户裁定 D1–D7 + Q15–Q28
- **目标**：负责人对决策稿全部待裁定项给出批准/否决/改判，闭合「待裁定」列。
- **验收证据**：决策稿中每项「待裁定」有负责人签字/批注；与收敛稿冲突处已以本文 C 表为准。
- **当前状态**：P1。建议已列，待批准（本文不代行批准）。
- **风险**：未裁定即实施 → 返工；否决项未清理 → 文档歧义。
- **回滚**：N/A（决策动作本身可逆）。

### G12 — 具体资源额度成本测算
- **目标**：基于真实单价（R2 存储/请求/即使免费出口也需算请求费、LLM token、ASR 时长）测算免费期与付费期额度，形成可上线报价。
- **验收证据**：成本表含真实报价来源链接与日期；免费期额度有成本上限约束；超阈值告警可触发。
- **当前状态**：P1。框架与待核实单价清单已在 R2 设计稿 §四与决策稿 E5/Q28 列出；**缺真实单价，禁止编造数字**。
- **风险**：编造免费额度 → 成本失控；忽略请求费 → 隐性超支。
- **回滚**：N/A（测算为规划动作）。
