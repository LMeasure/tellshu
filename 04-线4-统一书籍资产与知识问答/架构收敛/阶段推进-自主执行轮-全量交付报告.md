### 5.1 可信身份能力抽象接口规格

#### 5.1.1 设计目标与边界

使「能力不存在时系统完整、安全、可定义」且「能力接入时三谓词签名不变、零协议返工」。抽象层**只声明契约，不实现任何签发主体、不虚构可信根、不采购 KMS**；`org_unit` 的真实性仍标 `[待决策]`，不宣称证明（A/B 分离）。

#### 5.1.2 接口定义（设计级规格，未执行）

```
interface EvidenceTrustProvider:
  # ① 能力状态探测（不得缓存为「已具备」）
  fn capability_state() -> enum { ABSENT, DEGRADED, AVAILABLE }

  # ② 证据登记（对应三主体之 ① collector）
  fn register_evidence(sid, payload, payload_sha256,
                       collector_id, collector_org_unit,
                       signature, signature_key_id,
                       r2_operation_id) -> Result<EvidenceHandle, Reject>

  # ③ 独立复核（对应三主体之 ② verifier）
  fn independent_verify(evidence_record_id,
                        verifier_id, verifier_org_unit,
                        verified_payload_sha256,
                        verification_result) -> Result<VerificationHandle, Reject>

  # ④ 签名密钥状态（双时点校验，对应 A5）
  fn key_state(key_id, signed_at) -> struct {
      valid_at_sign_time : boolean,      # signed_at ∈ [valid_from, valid_to]
      revoked_at         : timestamptz?, # 撤销：仅影响 signed_at > revoked_at
      compromised_at     : timestamptz?, # 泄露：影响该 key 全部证据
      org_unit           : text
  }

  # ⑤ 主体独立性校验（对应 A6，只做结构性判定）
  fn org_units_independent(c_org, v_org) -> boolean
```

#### 5.1.3 能力状态 → `terminalEvidenceAuthentic()` 子式映射（fail-closed 核心）

| 能力状态 | A2（复核记录） | A4（`r2_operation_id`） | A5（密钥） | A6（主体分离） | `Authentic()` | 系统行为 |
|---|---|---|---|---|---|---|
| **ABSENT（当前真实状态）** | FALSE（无复核记录） | **FALSE**（字段恒 NULL） | FALSE（密钥表为空） | FALSE（无可信 org_unit） | **恒 FALSE** | 无证据可进 `consumable` → 无消费 → `terminal_proven` 不可达 → T-REQUEUE 关闭 → 屏障 ABORT → **长期隔离稳态** |
| **DEGRADED**（部分能力到位，如仅有本地密钥） | 依记录 | FALSE | 依 `key_state` | 结构性可判但组织真实性不可证 | **FALSE** | 同上；告警 + 隔离，不降级放行 |
| **AVAILABLE**（全能力到位且 U-4 实测通过） | 依记录 | 依 R2 签名回执 | 依 `key_state` | 依可信登记 | 依 A1–A9 全式求值 | 仍需 U-4 十三条实测 + 白名单 4 来源可得 + 负责人重开裁定，**不自动开启重排** |
