## 三、WP-02 跨库架构唯一方案定案（§8.0 / §8.1 / §8.4 / §8.5 / §8.6）

### 3.1 十维度选型对比 → 唯一推荐 = 控制平面 Worker
新增 §8.0，对【独立控制平面 Worker】与【受控 postgres_fdw】在 10 维度比较：
访问边界 / 身份认证 / 网络隔离 / 超时重试 / 幂等 / 审计 / 数据一致性 / 故障恢复 / 权限最小化 / 运维复杂度。
**结论**：FDW 在 ②③⑤⑥⑦⑧ 至少 6 维不满足条件（隐式长连接、难请求级认证、无内置重试/幂等、难独立审计、易 TOCTOU 漂移、故障难区分），Worker 全维度满足 ⇒ 定案唯一方案。

### 3.2 完整执行流程（8 子点）+ TOCTOU + 版本绑定（§8.4）
① 发起组件（控制平面 Worker，非 PG 触发器）② 读 DB-A、不读 DB-B ③ 经显式认证 API 取可信数据
④ 验摘要+认证（HMAC 与签名分离校验）⑤ 写结果绑定不可变 ⑥ 处理 manifest 变化（高版本不一致→unverifiable）
⑦ Worker 崩溃/超时/重放（request_id 幂等、无半完成态）⑧ 失败不误判（未知态永不转 success）。
**TOCTOU 防范**：取数时点 T1 与写结果时点 T2 的时间窗，以【DB-A 当前 manifest_version 标识 + 取数 request_ts + 内容摘要 + 绑定不可变快照】四元组锁定，T2 不允许落后于 T1 版本。

### 3.3 完整核验协议（§8.5）
- **四类机制严格区分（不得混用，尤其不得把 HMAC 称非对称签名）**：
  ① 内容摘要 `manifest_content_sha256`（一致性，无密钥）② HMAC `manifest_hmac`（共享密钥消息认证）
  ③ 非对称签名 `manifest_signature`（私钥签发、独立公钥验，与 HMAC 分离存储与校验）④ 身份认证 `verified_by`/`verifier_org_unit`（操作者身份，与 ①②③ 正交）。
- **签名/MAC 覆盖字段（≥8）**：manifest_id、backup_id、recovery_run_id、requested_target_lsn、actual_stop_lsn、timeline、manifest_content_sha256、protocol_version。
- **密钥生命周期**：key_id / key_version / algorithm 显式；轮换宽窗内历史 key_version 仍可验（`historical_key_validation=true`）。
- **请求唯一标识 / 防重放 / 重试幂等**：request_id 全局唯一，(run_id, request_id) 去重；超 TTL 重放丢弃；崩溃重发用新 request_id。
- **审计记录**：每次核验（含 pending/unverifiable）写审计日志，位于 DB-B（恢复目标集群之外）。

### 3.4 故障语义 12 项（§8.6 + registry `fault_semantics_12`）
DB-A 不可用 / DB-B 不可用 / Worker 崩溃 / 网络超时 / manifest 删除 / manifest 变化 / 签名缺失 / HMAC 不一致 / 密钥过期 / 旧请求重放 / 重复请求 / 核验中断恢复。
**铁律**：未知态一律保持 pending / unverifiable，不得自动转 verified / success（registry 每项 `never_auto_success=true`）。

## 四、TRG-01 SQL 级并发正确性证明（§9.4 + registry）

### 4.1 重读真实 SQL（§1 注释态触发器，非仅 §9 文字）
锁定 §1 实际 SQL 五句：SQL-A 取证据本体（普通 SELECT）/ SQL-B 三主体+摘要闸门（布尔）/ SQL-C 槽位行锁 LO-1（FOR UPDATE）/ SQL-D created→verified（幂等 GET DIAGNOSTICS 允许 0 行）/ SQL-E verified→consumable（COUNT(DISTINCT channel)=6 才推进）。

### 4.2 READ COMMITTED 逐条可见性
- SQL-A/B：触发器内普通读/布尔，看见已提交数据，无脏读；同一命令内无新快照切换。
- SQL-C：FOR UPDATE 获取槽位行写锁；他事务持锁则**阻塞**（非读脏）；获锁后读他事务**已提交** state。
- SQL-D/E：在 LO-1 锁内执行；锁串行化使「读 state→判 COUNT→写 state」跨多语句无竞态；**不依赖 SERIALIZABLE**。

### 4.3 锁与并发路径 10 项（registry `lock_concurrency_paths_10`）
六串行/六并发/同 channel 重复/同 channel 异 verifier/第六通道精确触发/验证失败/verifier==collector/摘要不一致/同 sid 争槽位（普通阻塞非死锁）/部分提交后崩溃。逐条给出锁与终态。

### 4.4 最终状态 7 不变量（registry `final_invariants_7`）
I1 同 sid 不重复消费 / I2 6 个 channel 真实不同 / I3 未确认不推进 / I4 verifier-collector 隔离 / I5 payload hash 一致 / I6 consumable 仅原子产生（ROW_COUNT=1 CAS）/ I7 任意失败无部分成功（整事务 ROLLBACK）。
⇒ 7 不变量均可由 §1 真实 SQL + LO-1 行锁 + channel 唯一约束直接证明；若未来改动 §1 破坏任一条，校验器须同步修正并新增变异。
