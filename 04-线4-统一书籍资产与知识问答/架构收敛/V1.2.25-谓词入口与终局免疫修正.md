## 3. 三条验收标准对应的缺陷复现（基于 V1.2.24 原文，逐条定位）

### 3.1 V25-01｜T-S 可直接写 `copy_confirmed`，绕过 `copyConfirmed()`

| 位置 | 原文（摘录） | 问题 |
|---|---|---|
| **V1.2.24 §6.4 L432–436** | `state = CASE :decision WHEN 'confirm_success' THEN 'copy_confirmed' WHEN 'confirm_not_applied' THEN 'copy_failed_retry' WHEN 'require_reupload' THEN 'awaiting_reupload' ELSE state END` | **T-S 直接把 P3/P5 升格为 P2 `copy_confirmed`**（以及 P4、终局），完全没有调用 `copyConfirmed()` |
| V1.2.24 §6.4 L415 | `IF settlementEvidenceSufficient(v, :evidence) IS NOT TRUE THEN ... RETURN` | 守卫谓词**全文未定义**；名字暗示「证据充分即可改状态」，实际不校验九项证据 |
| V1.2.24 §6.4 L424 | `settlement_decision ... -- 'confirm_success' \| 'confirm_not_applied' \| 'require_reupload'` | 三个 decision 都是**状态跃迁指令**，不是裁定记录 |
| **V1.2.24 §6.5 L463** | T-R 的 P2 分支：`IF copyConfirmed(:intent, :candidate) IS NOT TRUE THEN COMMIT; RETURN; END IF;` | T-R 有谓词守卫，但 **T-S 提供了另一条无守卫的 P2 入口** |
| V1.2.24 §6.5 L480 | T-R 的 P4 分支：`IF (:ev->>'not_applied') IS DISTINCT FROM 'true' THEN ... RETURN` | T-S 的 `confirm_not_applied` 同样绕过 P4 证据守卫 |
| **V1.2.23 L467 / L500 / L854（上游）** | P2 定义「由 `copyConfirmed()` 谓词确认」；「P2 进入条件 = 九项全真，负责事务 T-R」；不变量 #9「`copy_confirmed` 必须满足统一证据谓词」 | T-S 的入口**直接违反**上游定义与不变量 #9 |
| V1.2.23 §9.3 L672（上游） | 「❌ 不得把 `copy_unknown` 自动升级为 `copy_confirmed`」 | 人工裁定路径成为该禁令的旁路 |

> **后果（静态推演）**：一个 U-4 未实测、证据不足的 P3 `copy_unknown` 意图，可由 T-S 的 `confirm_success` 直接置为 P2 → T-C1/T-C2 登记 `content_blobs` 并置 `committed` → **未通过九项证据谓词却写入了正式资产**。这是「绕过 `copyConfirmed()`」的完整可达路径，验收标准 1 在 V1.2.24 文本下**不成立**。

### 3.2 V25-02｜终局可被重复裁定，旧请求无 DB 级免疫

| **V1.2.24 §5.1 L267–269** | `AND (e.request_phase IN ('resolved','failed','none')) IS TRUE` / `AND COALESCE(e.unresolved_request, true) IS FALSE` / **`AND (e.resolved_at IS NOT NULL) IS TRUE`** | 三个条件对 `done` 与 `skipped` **统一要求**，未按分支区分 |

## 4. V25-01：T-S 无法绕过 `copyConfirmed()`

### 4.1 唯一入口原则（设计级硬约束）

> **P2 `copy_confirmed` 的唯一写入者 = T-R**；任何事务要写 `state='copy_confirmed'`，必须在**同一 PG 事务内**同时满足：
> ① `copyConfirmed()` 九项逐项 `COALESCE` 后整体 `IS TRUE`（V1.2.23 §9 / V1.2.24 §4.4）；
> ② 写入 `confirmed_evidence` JSONB（九项键值齐全且均为 `'true'`）；
> ③ 写入 `writer_tx='T-R'`；
> ④ 满足 INV-6（`request_phase='resolved'` ∧ `resolved_at IS NOT NULL` ∧ `unresolved_request IS FALSE`）。
> **T-S、T-SKIP、T-TERM、T-C1、T-C2、Reconciler、迁移脚本、手工 DML 一律不得写 P2。**

### 4.2 新增设计级列与 DB 级证据门触发器（不执行）

```
promotion_intents 增补列（设计级）:
  writer_tx            text NOT NULL DEFAULT 'unknown'   -- 写入事务身份，R1 偏危险
  confirmed_evidence   jsonb                            -- 九项键 E_op..E_freeze，值 'true'/'false'
  confirmed_gate       boolean NOT NULL DEFAULT false    -- T-R 在本事务内求值通过的持久凭证
  settlement_decision  text                             -- 裁定记录（非跃迁指令）
```

```sql
-- 设计级 BEFORE INSERT OR UPDATE 触发器（不执行）；全部比较 NULL-safe（R6）
CREATE FUNCTION trg_assert_copy_confirmed_gate() RETURNS trigger AS $$
DECLARE v_true int;
BEGIN
  IF NEW.state = 'copy_confirmed' THEN
     -- ① 写入者必须是 T-R
     IF (COALESCE(NEW.writer_tx,'') = 'T-R') IS NOT TRUE THEN
        RAISE EXCEPTION 'p2_only_via_T-R';
     END IF;
     -- ② 九项证据必须齐全且全部为 'true'（DB 层可独立复算的部分）
     SELECT count(*) INTO v_true
       FROM jsonb_each_text(COALESCE(NEW.confirmed_evidence, '{}'::jsonb))
      WHERE (value = 'true') IS TRUE;
     IF (v_true = 9) IS NOT TRUE THEN
        RAISE EXCEPTION 'copyConfirmed_nine_flags_incomplete';
     END IF;
     -- ③ 本事务内求值凭证
     IF (NEW.confirmed_gate IS TRUE) IS NOT TRUE THEN
        RAISE EXCEPTION 'copyConfirmed_not_evaluated_in_tx';
     END IF;
     -- ④ INV-6 字段组合
     IF (NEW.request_phase = 'resolved'
         AND NEW.resolved_at IS NOT NULL
         AND NEW.unresolved_request IS FALSE
         AND NEW.result_confirmed_at IS NOT NULL) IS NOT TRUE THEN
        RAISE EXCEPTION 'p2_field_invariant_violated';
     END IF;
  END IF;
  RETURN NEW;
END $$;
```
> **诚实边界**：该触发器能独立验证「九项证据**在 PG 内齐全且标记为 true** + 写入者身份 + 字段组合」，但**不能独立复算 R2 侧证据的可信性**（E_content/E_version/E_op 的来源是 U-4）。若 T-R 被伪造证据欺骗，DB 层无法察觉 —— 这是 PG 侧能力的上限，须在 §11 U-4 阻断项中如实登记。

### 4.3 T-R 的 P2 分支补齐（在 V1.2.24 §6.5 L461–468 基础上）


### 4.4 T-S 重写：从「状态跃迁」改为「裁定记录 + 证据转交」（不执行）

> `settlementEvidenceSufficient()` **改名并重定义**为 `settlementEvidenceAuditable()`：只判定「裁定证据可审计 ∧ 无未确认 R2 请求」，**不授予任何状态跃迁权**，也**不是 `copyConfirmed()` 的替代**。

```
settlement_decision 封闭枚举（重定义）:
  'evidence_forwarded'  -- 证据已转交 T-R 重新求值；T-S 不写 state
  'require_reupload'    -- 由 T-TERM 写 awaiting_reupload（唯一允许的终局写入，见 §5.3）
  'insufficient'        -- 只写 adjudication_log，不动主行
```

```sql
-- T-S：唯一职责 = 记录裁定 + 清理「请求是否未确认」字段；不写 state / result_confirmed_at / promoted_at / lease_epoch
BEGIN;
  SELECT state, request_phase, resolved_at, unresolved_request, settled_at, lease_epoch
    INTO v FROM promotion_intents WHERE intent_id=:iid FOR UPDATE;

  -- 单次裁定守卫（V25-02）：已裁定 → 只写 append-only 审计，不 UPDATE 主行
  IF (v.settled_at IS NULL) IS NOT TRUE THEN
     INSERT INTO adjudication_log(intent_id, outcome) VALUES (:iid, 'duplicate_adjudication_rejected');
     COMMIT; RETURN;
  END IF;

  IF settlementEvidenceAuditable(v, :evidence) IS NOT TRUE THEN
     INSERT INTO adjudication_log(intent_id, outcome) VALUES (:iid, 'insufficient_evidence');
     COMMIT; RETURN;                    -- 保持 unresolved_request=true / resolved_at=NULL
  END IF;

  IF (:decision = 'evidence_forwarded') IS TRUE THEN
     UPDATE promotion_intents
        SET settled_at          = now(),
            settlement_evidence = :evidence,
            settled_by          = :operator,
            settlement_decision = 'evidence_forwarded',
            unresolved_request  = false,
            -- ★ 不写 state；request_phase / resolved_at 也保持不变
            -- ★ 证据合并进 result_evidence，供 T-R 重放时读取
            result_evidence     = COALESCE(result_evidence,'{}'::jsonb) || :evidence
      WHERE intent_id=:iid AND lease_epoch=:mine
        AND (settled_at IS NULL) IS TRUE
        AND (state NOT IN (<终局集合>)) IS TRUE;
     -- 随后由 T-R 重放（§4.5）；若 copyConfirmed() 仍不为真，保持 P3/P5 + 隔离
  ELSIF (:decision = 'require_reupload') IS TRUE THEN
     -- 交由 T-TERM（§5.3）写终局；本事务只记录裁定意图
     INSERT INTO adjudication_log(intent_id, outcome, decision)
       VALUES (:iid, 'forwarded_to_T-TERM', 'require_reupload');
  ELSE
     INSERT INTO adjudication_log(intent_id, outcome) VALUES (:iid, 'insufficient');
  END IF;
COMMIT;
```

### 4.5 证据转交后的唯一合法推进路径

```
T-S(evidence_forwarded) → result_evidence 合并 + settled_at 落库（state 仍 P3/P5）
        │
        ▼
T-R 重放（WHERE state IN ('copy_unknown','quarantined')
          AND settled_at IS NOT NULL AND lease_epoch=:mine）
        │
        ├─ copyConfirmed() IS TRUE  → 写 P2（writer_tx='T-R', confirmed_evidence 九项, confirmed_gate=true）
        │                            → 触发器独立复核通过 → T-C1/T-C2
        └─ IS NOT TRUE              → 保持 P3/P5 + 隔离；禁止自动升级
```
> **关键**：人工裁定只能「提供证据」，**不能「宣布结果」**；结果必须由 `copyConfirmed()` 判定、`T-R` 写入、DB 触发器复核。这是验收标准 1 的实质闭环。

### 4.6 全路径拦截表（验收判定依据）

| 试图写 `state='copy_confirmed'` 的路径 | 拦截层 | 结果 |
|---|---|---|
| **T-S `confirm_success`（V1.2.24 §6.4 L433）** | ① decision 枚举已删除该值 ② T-S 不再写 `state` ③ 即使硬写，触发器 `writer_tx<>'T-R'` 拒绝 | ❌ 被拒 |

## 5. V25-02：终局状态不可被重复裁定或旧请求覆盖

### 5.1 终局集合（真实状态值，唯一定义）

```
TERMINAL_STATES(promotion_intents) =
    'promoted'(P7)                              -- 业务完成，天然终局
  | 'awaiting_reupload'                        -- 要求重传，天然终局
  | 'quarantined'(P5) AND settled_at IS NOT NULL
        AND unresolved_request IS FALSE        -- 条件终局（沿用 V1.2.23 L535/L607 的 settled 要求）

TERMINAL_STATES(object_outbox) =
    'done' | 'skipped'  （且 settled_at/terminal_at 已落库）   -- 事件级终局（V1.2.23 §5.3）
```
> **明确**：`quarantined` 但 `settled_at IS NULL` **不是终局**（仍待裁定）；`copy_unknown`(P3) / `dead_letter` / `deferred` / `unknown` 一律不是终局。

**受终局免疫保护的字段**（设计级）：`state`、`request_phase`、`resolved_at`、`unresolved_request`、`result_evidence`、`confirmed_evidence`、`confirmed_gate`、`writer_tx`、`settled_at`、`settlement_evidence`、`settled_by`、`settlement_decision`、`lease_epoch`、`promoted_at`、`result_confirmed_at`。仅允许 `adjudication_log` / 审计表 **append-only 追加**。

### 5.2 单次裁定守卫（设计级，不执行）

```
所有裁定类事务（T-S / T-SKIP / T-TERM）的 UPDATE 必须同时满足：
    (settled_at IS NULL) IS TRUE                       -- 未裁定过
AND (state NOT IN (TERMINAL_STATES)) IS TRUE           -- 非终局
AND (lease_epoch = :mine) IS TRUE                     -- fencing
AND (request_id = :rid) IS TRUE                       -- 请求身份（若有）
AND (unresolved_request IS TRUE) IS TRUE  [仅当需要清理时]
```
- 一旦裁定，`settled_at` 非空 → 后续任何裁定事务 `WHERE settled_at IS NULL` 不匹配 → **0 行幂等退出**。
- 重复裁定**只允许**写 `adjudication_log(outcome='duplicate_adjudication_rejected')`，**不得 UPDATE 主行**（审计追加与状态写入分离）。
- 补入 INV-8：`settled_at IS NOT NULL ⇒ 禁止再裁定`（由触发器 + 守卫共同保证）。

### 5.3 T-TERM：唯一 `awaiting_reupload` 入口（从 T-S 拆出，不新增主题）

```sql
-- 设计级；仅由人工裁定「源与 temp 均不可恢复」触发
BEGIN;
  SELECT state, settled_at, unresolved_request, lease_epoch
    INTO v FROM promotion_intents WHERE intent_id=:iid FOR UPDATE;
  IF (v.settled_at IS NULL) IS NOT TRUE
     OR reuploadEvidenceAuditable(:evidence) IS NOT TRUE
     OR (v.state NOT IN ('copy_unknown','quarantined')) IS TRUE THEN
     INSERT INTO adjudication_log(...) VALUES (..., 'T-TERM_rejected');
     COMMIT; RETURN;
  END IF;
  UPDATE promotion_intents
     SET state='awaiting_reupload', settled_at=now(), settled_by=:operator,
         settlement_decision='require_reupload', settlement_evidence=:evidence,
         unresolved_request=false, writer_tx='T-TERM'
   WHERE intent_id=:iid AND lease_epoch=:mine
     AND (settled_at IS NULL) IS TRUE
     AND (state NOT IN (TERMINAL_STATES)) IS TRUE;
COMMIT;
```
> T-TERM 是 V1.2.24 §6.4 中 `require_reupload → awaiting_reupload` 分支的**职责拆分**，不是新功能：把唯一允许的终局写入从「通用裁定事务」隔离到「专用事务」，便于单次守卫与终局免疫统一施加。

### 5.4 终局免疫触发器（DB 级最后一道，设计级不执行）

```sql
CREATE FUNCTION trg_no_mutation_after_terminal() RETURNS trigger AS $$
BEGIN
  IF TG_OP = 'UPDATE' THEN
     IF (OLD.state IN ('promoted','awaiting_reupload')
         OR (OLD.state = 'quarantined' AND OLD.settled_at IS NOT NULL
             AND OLD.unresolved_request IS FALSE)) IS TRUE THEN
        IF NEW.state IS DISTINCT FROM OLD.state
           OR NEW.request_phase IS DISTINCT FROM OLD.request_phase
           OR NEW.resolved_at IS DISTINCT FROM OLD.resolved_at
           OR NEW.unresolved_request IS DISTINCT FROM OLD.unresolved_request
           OR NEW.result_evidence IS DISTINCT FROM OLD.result_evidence
           OR NEW.confirmed_evidence IS DISTINCT FROM OLD.confirmed_evidence
           OR NEW.confirmed_gate IS DISTINCT FROM OLD.confirmed_gate
           OR NEW.writer_tx IS DISTINCT FROM OLD.writer_tx
           OR NEW.settled_at IS DISTINCT FROM OLD.settled_at
           OR NEW.settlement_evidence IS DISTINCT FROM OLD.settlement_evidence
           OR NEW.settled_by IS DISTINCT FROM OLD.settled_by
           OR NEW.settlement_decision IS DISTINCT FROM OLD.settlement_decision
           OR NEW.lease_epoch IS DISTINCT FROM OLD.lease_epoch
           OR NEW.promoted_at IS DISTINCT FROM OLD.promoted_at
           OR NEW.result_confirmed_at IS DISTINCT FROM OLD.result_confirmed_at THEN
           RAISE EXCEPTION 'terminal_state_immutable';
        END IF;
     END IF;
  ELSIF TG_OP = 'INSERT' THEN
     -- 禁止绕过状态机直接插入终局行（恢复/迁移脚本须走显式重建流程）
     IF (NEW.state IN ('promoted','awaiting_reupload')) IS TRUE
        AND (COALESCE(NEW.terminal_origin,'') = '') IS TRUE THEN
        RAISE EXCEPTION 'terminal_insert_requires_origin';
     END IF;
  END IF;
  RETURN NEW;
END $$;
```
> 全部用 `IS DISTINCT FROM` / `IS TRUE` / `COALESCE`（V1.2.24 R2/R3/R6），避免 CHECK/IF 的 UNKNOWN-through。

### 5.5 旧请求三重 fencing 与诚实边界

| 层 | 机制 | 能防什么 | 不能防什么 |
|---|---|---|---|
| ① CAS | `lease_epoch=:mine` ∧ `request_id=:rid` ∧ `state NOT IN TERMINAL` ∧ `settled_at IS NULL` | 不同代次旧 Worker、同代次重复调用、对终局行的写入 | 忘带 WHERE 的运维 DML |
| ② 身份 | `writer_tx` 由事务显式写入，触发器按写入者校验入口权限 | 非授权事务写 P2 等关键状态 | 应用角色被提权后伪造 `writer_tx`（须权限矩阵治理） |
| ③ DB 触发器 | `trg_no_mutation_after_terminal()` 在 UPDATE/INSERT 时强制 | 任何绕过应用层的 UPDATE/INSERT（含迁移、手工） | **R2 侧已发出的迟到请求** |

> **跨系统诚实边界**：以上三层都是 **PG 侧**保护。旧 Worker 的 **R2 COPY / DELETE 迟到成功**不受任何 PG 机制约束，仍由 `result_evidence` 比对 + P5 隔离人工裁定处理（V1.2.23 §4.2 #8、§8.4）。本轮**不宣称消除了跨系统迟到副作用**。

### 5.6 验收判定表

| 攻击 / 故障路径 | 拦截层 | 结果 |
|---|---|---|
| 两名操作员先后对同一意图裁定 | `settled_at IS NULL` 单次守卫 → 第二次 0 行 + `adjudication_log` | ❌ 主行不改写，审计链完整 |
| 对 `awaiting_reupload` 行再次 T-S | ① 该状态已从 §6.4 L439 允许列表移除 ② 终局免疫触发器 | ❌ 被拒 |

## 6. V25-03：`abortSatisfied()` 每个允许分支在字段不变量下实际成立

### 6.1 根因：事件表缺少专属字段不变量

> V1.2.24 §6.3 的 INV-1～INV-8 全部写在 **`promotion_intents`** 上；`abortSatisfied()` 作用在 **`object_outbox` 事件行**上。两表同名字段（`request_phase` / `resolved_at` / `unresolved_request`）语义未对齐，且**没有任何事务被定义为事件行这些字段的写入者**。本轮先补事件表不变量，再证明分支可满足。

### 6.2 Outbox 事件专属 `EVENT-INV-1～8`（设计级，NULL-safe，R3）

```
EVENT-INV-1  status / request_phase / unresolved_request 均 NOT NULL；
             DEFAULT 偏危险（'pending' / 'none' / true）；writer_tx NOT NULL DEFAULT 'unknown'
EVENT-INV-2  request_phase='registered' ⇒
             (request_id IS NOT NULL AND unresolved_request IS TRUE AND resolved_at IS NULL)
EVENT-INV-3  status='done' ⇒
             (request_phase IN ('resolved','failed') AND resolved_at IS NOT NULL
              AND unresolved_request IS FALSE AND result_evidence IS NOT NULL)
EVENT-INV-4  status='skipped' ⇒
             (request_phase='none' AND resolved_at IS NULL
              AND skip_reason IN (<白名单>) AND skip_evidence IS NOT NULL
              AND settled_at IS NOT NULL AND settled_by IS NOT NULL)
             ★ skipped = 「请求确定未发 + 目标已由他者/枚举证明达成」，故 resolved_at 为 NULL
EVENT-INV-5  status IN ('unknown','dead_letter','deferred','leased','in_flight') ⇒
             (resolved_at IS NULL) ；其中 registered 相位须 unresolved_request IS TRUE
EVENT-INV-6  settled_at IS NOT NULL ⇒
             (settled_by IS NOT NULL AND settlement_evidence IS NOT NULL
              AND status IN ('done','skipped','quarantined','awaiting_reupload'))
EVENT-INV-7  abort_evidence IS NOT NULL ⇒ 必需键齐全且值非 NULL；
             upload_id_terminal / enum_recheck 为 'true' 时须有 enum_recheck_at + evidence_source
EVENT-INV-8  settled_at IS NOT NULL ⇒ 禁止再裁定（配合 §5.2 单次守卫）
```
> 所有 `⇒` 实现为 `CHECK ((NOT (<前件>) OR (<后件>)) IS TRUE)`（V1.2.24 R3）；事件行 `writer_tx` 与终局免疫触发器（§5.4）同样施加。

### 6.3 `abortSatisfied()` 拆为两个自洽子谓词（消除 `skipped` 矛盾）

```
abortSatisfied(e) := ( abortDoneSatisfied(e) OR abortSkippedSatisfied(e) ) IS TRUE
-- 注：FALSE OR UNKNOWN = UNKNOWN，整体 IS TRUE 收口 → UNKNOWN 变 FALSE（V1.2.24 R2）

共同前提（两分支都要求）:
    (e.event_type='ABORT_MPU' AND e.step_no=1) IS TRUE
AND (e.abort_evidence IS NOT NULL) IS TRUE                      -- R7
AND COALESCE(e.abort_evidence->>'upload_id_terminal','false') = 'true'
AND COALESCE(e.abort_evidence->>'enum_recheck','false')       = 'true'   -- U-4 #7/#8
AND ( (COALESCE(e.abort_evidence->>'fence_gen','-1') = :current_fence_gen)
      OR (e.cross_gen_adjudication IS NOT NULL AND e.settled_at IS NOT NULL) ) IS TRUE
        -- ★ 新增跨代裁定分支，使跨屏障清理可达（须人工裁定，不默认放行）

abortDoneSatisfied(e) :=
    共同前提
AND (e.status='done') IS TRUE
AND (e.request_phase IN ('resolved','failed')) IS TRUE
AND (e.resolved_at IS NOT NULL) IS TRUE
AND (e.unresolved_request IS FALSE) IS TRUE
AND (e.request_id IS NOT NULL) IS TRUE
   → 与 EVENT-INV-2(转出前)/INV-3/INV-7 相容

abortSkippedSatisfied(e) :=
    共同前提
AND (e.status='skipped') IS TRUE
AND (e.request_phase='none') IS TRUE                    -- 请求确定未发
AND (e.resolved_at IS NULL) IS TRUE                     -- ★ 不再要求非空（核心修正）
AND (e.unresolved_request IS FALSE) IS TRUE             -- 由 T-SKIP 显式结算
AND (e.skip_reason IN ('upload_id_already_terminated_by_other_worker',
                       'upload_id_never_existed')) IS TRUE
AND (e.skip_evidence IS NOT NULL) IS TRUE               -- 含他者 outbox_id 或全量枚举
AND (e.settled_at IS NOT NULL AND e.settled_by IS NOT NULL) IS TRUE  -- ★ 裁定凭证替代 resolved_at
   → 与 EVENT-INV-1/4/6/7/8 相容
```

### 6.4 新增 T-SKIP 裁定事务（为 `skipped` 分支提供字段写入者，设计级不执行）

```sql
-- 仅在「请求从未发出」且枚举复核证明 UploadId 已终止/从未存在时，由人工/只读取证触发
BEGIN;
  SELECT status, request_phase, resolved_at, unresolved_request, settled_at, lease_epoch
    INTO v FROM object_outbox WHERE outbox_id=:id FOR UPDATE;

  IF (v.request_phase='none') IS NOT TRUE
     OR (v.settled_at IS NULL) IS NOT TRUE
     OR (v.status IN ('done','skipped')) IS TRUE
     OR skipEvidenceAuditable(:evidence, :skip_reason) IS NOT TRUE THEN
     INSERT INTO adjudication_log(...) VALUES (..., 'T-SKIP_rejected');
     COMMIT; RETURN;
  END IF;

  UPDATE object_outbox
     SET status='skipped',
         request_phase='none',          -- 保持：请求确定未发
         resolved_at=NULL,              -- ★ 保持 NULL（EVENT-INV-4）
         unresolved_request=false,      -- ★ 显式结算：无在途请求
         skip_reason=:skip_reason,
         skip_evidence=:evidence,
         abort_evidence=:abort_ev,      -- 与 §5.2 统一结构，含 enum_recheck
         settled_at=now(), settled_by=:operator, settlement_evidence=:evidence,
         writer_tx='T-SKIP'
   WHERE outbox_id=:id AND lease_epoch=:mine
     AND (request_phase='none') IS TRUE
     AND (settled_at IS NULL) IS TRUE
     AND (status NOT IN ('done','skipped')) IS TRUE;
COMMIT;
```
> 同时补 **T-R-outbox**（Abort 事件结果回写）作为 `done` 分支的写入者：`request_phase='resolved'|'failed'`、`resolved_at=now()`、`unresolved_request=false`、`result_evidence`/`abort_evidence` 落库，受 `writer_tx='T-R-outbox'` 与终局免疫约束。
