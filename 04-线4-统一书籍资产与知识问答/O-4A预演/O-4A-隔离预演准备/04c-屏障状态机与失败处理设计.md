## 1. 第九轮缺陷与第十轮修复映射

| # | 第九轮缺陷 | 第十轮修复 |
|---|---|---|
| B1 | `arrive()` 先 `UPDATE reached` 后 `LISTEN` → 最后到达者 NOTIFY 时先到者尚未 LISTEN，**通知丢失**，永久阻塞 | 拆出 **listener_ready 阶段**：所有参与者先建立 LISTEN 并登记 `listeners_ready`，协调侧确认 `listeners_ready==total` 后才允许进入 arrive；NOTIFY 仅在全部监听就绪后发出 |
| B2 | `conn.wait()` 并非 psycopg3 公开通知接口（官方文档无此方法说明） | 改用 `conn.notifies(timeout=..., stop_after=...)`，官方接口 |
| B3 | psycopg2「兼容」注释为虚假承诺（通知接口、事务语义不同） | 移除 psycopg2 fallback；启动强制校验 `psycopg>=3.2.4`，不满足即退出码 91 |
| B4 | 屏障计数/释放状态仅在单表两列，无到达/完成事件，无法追溯崩溃 | 新增 `rehearsal_barrier_events` 四状态事件表；屏障状态持久化，可重放、可诊断 |
| B5 | 无超时/重复到达/崩溃处理；等待可能无限挂死 | `_await` 带 deadline；通知仅唤醒、真值在表，`notifies(timeout)` 超时重读真值；见 §4 |
| B6 | 用 `time.sleep` 风险 | 全文零 sleep；等待全部为事件驱动 + 持久化真值 |

## 2. 状态协议（四状态，持久化在 `rehearsal_barriers` + `rehearsal_barrier_events`）

```
                      ┌——————————————————————————————————————————————┐
                      │  每个参与者在独立 autocommit listener 连接上    │
                      └──——————————————————————————————————————————————┘
  [初始]  ──LISTEN ready/release──▶  listener_ready
                                        │ 登记 listeners_ready += 1（事件表记一行）
                                        ▼
                              协调侧等齐 listeners_ready == total
                                        │
                                        ▼  （此时全部 NOTIFY 监听已建立）
                             participant_arrived
                                        │ reached += 1（事件表记一行）
                                        │ 最后到达者：released=true + NOTIFY release_ch
                                        ▼
                                 barrier_released
                                        │ 等待者 notifies(timeout) 被唤醒 → 重读 released 真值
                                        │ 各会话执行自身业务 SQL 并 COMMIT/ROLLBACK
                                        ▼
                            participant_completed
                                        │ completed += 1（事件表记一行）
                                        ▼ 协调侧确认 completed == total
                                      [结束]
```

### 2.1 状态字段与常量

| 状态事件（event 枚举） | 计数器/标志 | 写入者 | 语义 |
|---|---|---|---|
| `listener_ready` | `listeners_ready += 1` | 各参与者 listener 连接 | LISTEN 已建立，能接收通知 |
| `participant_arrived` | `reached += 1` | 各参与者 listener 连接 | 已到达屏障点、准备执行 SQL |
| `barrier_released` | `released = true` | **最后**到达者 | 全部到达，放行（NOTIFY 只在此刻发出） |
| `participant_completed` | `completed += 1` | 各参与者 listener 连接 | 业务 SQL 已结束 |

关键纪律：**所有屏障写操作走独立 autocommit listener 连接，绝不进入业务事务**。否则业务 RAISE 回滚会把到达计数一并回滚，导致其他会话永久等待（第九轮隐患）。

### 2.2 为什么能根除通知丢失（B1）

psycopg 官方明确：`Before 3.2.4, notification received between calling LISTEN and starting the generator were lost`。第十轮用两阶段从协议层规避：
1. 每个参与者先 `LISTEN ready_ch/release_ch` 并启动 `notifies()` 生成器，随即登记 `listener_ready`。
2. 协调侧（每个参与者侧都做一次）等待 `listeners_ready == total`，确认所有会话的 LISTEN 都已建立。
3. 只有最后到达者在 `reached == total` 时才 `NOTIFY release_ch`。此时所有监听已就位。
4. 即便个别通知仍丢失/延迟，`_await` 在 `notifies(timeout=5s)` 到期后**重读 `released` 真值表**，不会永久阻塞；丢失次数记入 `evidence.notify_missed`。

## 3. 状态机迁移表（合法迁移）

| 当前 | 事件 | 条件 | 下一状态 | 动作 |
|---|---|---|---|---|
| 初始 | LISTEN 建立 | 连接就绪 | listener_ready | 写事件 + `listeners_ready+1` |
| listener_ready | 全部监听就绪 | `listeners_ready==total` | 允许 arrive | 协调侧放行（不发 NOTIFY） |
| 允许 arrive | 到达 | 每次到达 | participant_arrived | 写事件 + `reached+1` |
| participant_arrived | 最后到达 | `reached==total` | barrier_released | `released=true` + `NOTIFY release_ch` |
| participant_arrived | 未到齐 | `reached<total` | 等待 | `notifies(timeout)` + 重读真值 |
| barrier_released | 业务结束 | 每会话完成 | participant_completed | 写事件 + `completed+1` |
| participant_completed | 全部完成 | `completed==total` | 结束 | 证据判定 |

非法迁移（如 `released` 在 `reached<total` 时为 true）不由应用触发；若观测到，`evidence` 判 FAIL 并记入 `barrier_events`。

## 4. 失败处理表

| 失败类型 | 检测方式 | 处理 | 证据字段 / verdict |
|---|---|---|---|
| 通知丢失/延迟 | `notifies(timeout=5s)` 一轮未收到目标通道通知 | 重读 `released`/`completed` 真值表；不阻塞 | `notify_missed += 1` |
| 等待超时 | `_await` 达 `BARRIER_DEADLINE=45s` 仍未满足真值 | 抛 `TimeoutError`；该用例 `verdict=TIMEOUT` | `verdict=S_TIMEOUT` |
| 参与者崩溃（业务会话） | 该会话未写 `participant_completed`，连接已断 | 协调侧 `completed<total` → 用例 `PARTIAL`；不误判 PASS | `verdict=S_PARTIAL` |
| 参与者崩溃（监听会话） | `listeners_ready<total` 达 deadline | `TimeoutError` → `TIMEOUT`，记录已 ready 的 pid | `verdict=S_TIMEOUT` |
| 协调者/编排器崩溃 | 整个进程终止 | 屏障状态留在 DB；重跑由 `setup()` 幂等重置 `reached/listeners_ready/released/completed=0` | 新 run_id，不覆盖旧证据 |
| 重复到达（重放） | 同一 pid 多次 `participant_arrived` | 真值以计数为准；事件表留多行为可审计；`reached` 超过 total 视为异常 FAIL | `barrier_events` + FAIL |
| 业务 RAISE 回滚 | 业务连接异常 | 仅回滚业务事务；屏障计数在 listener 连接已落盘，不受影响 | `SessionResult.outcome=ROLLBACK(...)` |
| psycopg 版本过低 | 启动 `assert_psycopg_version()` | 退出码 91，拒绝运行 | stderr |

## 5. 与确定性（无 sleep）的兼容说明

- 等待原语只有两个：`conn.notifies(timeout=...)`（事件阻塞，内核 epoll/select，非轮询 sleep）与真值表读。
- `timeout=5s` 是**安全兜底上限**而非时序猜测：真值在 DB，超时只触发重读，不改变并发语义。
- 锁等待证据仍由独立 monitor 连接在**提交前**采样 `pg_locks`/`pg_blocking_pids` 取得（见 06），屏障不替代锁观测。

## 6. 版本依据（本轮 WebFetch 官方查证，记录可复核）

- `psycopg 3.3.9 · Connection classes`：`notifies(*, timeout: float|None=None, stop_after: int|None=None)`；原文 **"Changed in version 3.2: Added timeout and stop_after parameters."** ⇒ `timeout` 自 3.2 可用。
- `psycopg 3.3.9 · Concurrent operations / Asynchronous notifications`：建议 LISTEN/NOTIFY 用 **autocommit** 连接；原文 **"Before Psycopg 3.2.4, notification received between calling LISTEN and starting the generator were lost."** ⇒ 下限取 **3.2.4**。
- 同页：生成器与 handler 不可混用（3.2.10 起混用告警）；本套件**只用生成器**，符合单一路径。
- URL（授权后复核用）：`https://www.psycopg.org/psycopg3/docs/api/connections.html`、`https://www.psycopg.org/psycopg3/docs/advanced/async.html`。

> `[待PG]` 上述均为官方文档结论与静态设计；真实 PG18 上的通知时序、锁等待图、txid 可见性仍须预演实测，本轮不构成实测证据。
