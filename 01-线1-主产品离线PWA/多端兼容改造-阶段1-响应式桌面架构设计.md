+----------+-------------------------------------------------------+
| ≡ 述树   |                                                       |

| 首页     |            主内容区（max-w-1200 居中）                 |
| 发现     |                                                       |

| 词库     |                                                       |

- **左侧**：固定侧栏，主导航 = 现有 4 个 Tab（保证导航语义不丢失），下分组收纳其余**已存在**的路由；可折叠为图标态。

## 2. 断点与档位

| 档 | 视口 | 布局 | 导航 | 内容宽 |
|---|---|---|---|---|
| **M 移动/平板** | `< 1024px`（含 390 / 768） | **与今天完全一致**（`.app-frame` 375px 居中 + 阴影） | 底部 Tab + 底部 SearchDock | `max-w-app` 375px |
| **D 桌面** | `≥ 1024px`（lg，含 1024/1366/1440/1920） | 侧栏 + 顶栏 + 内容区；**不再使用 `.app-frame`** | 侧栏 + 顶栏（底部 Tab/SearchDock 不渲染） | 列表 `max-w-[1200px]`；阅读 `max-w-[760px]` |

**为什么用 `lg(1024)` 作为唯一分界**：
- 任务书要求覆盖的 6 档里，1024/1366/1440/1920 全部落在桌面档，768/390 落在移动档，**两档即可全覆盖**，不必三档，回归面最小。
- 768px 归入移动档 = 「小屏幕自动切换为适合移动端的布局」，满足任务书要求，且移动端行为零变化。

> 可选增强（**本期不做**，列为后续）：T2 平板档 `640–1023px` 把内容放宽到 `max-w-[560px]`，让平板不出现过大留白。

## 3. 组件改造清单

> 核心原则：**桌面分支完全新增，移动分支字节级不变**。这样移动端零回归，也避免与占用中的 `index.css` 冲突。

### 3.1 新增 `src/hooks/useIsDesktop.ts`（新文件）
- `matchMedia('(min-width: 1024px)')` + `change` 监听，返回 boolean。
- **必要性**：AppShell 需要一个分支开关。
- **为何用 JS 而非纯 CSS `lg:hidden`**：纯 CSS 会同时把两套导航渲染进 DOM（两份 `<nav>`、重复可聚焦元素），无障碍与键盘导航会重复；用 JS 分支只渲染一套，语义干净。代价是首帧需一次判定（初值用 `matchMedia` 同步读取，**不会闪烁**）。

### 3.2 新增 `src/components/layout/SideNav.tsx`（新文件）
- 复用 `BottomTabBar` 的 `TABS` 常量与 `shushu` 图标、`NavLink` 激活态（`text-primary`），竖排渲染；加折叠态（图标 only）。
- 分组：主导航（首页/发现/复习/我的） + 学习（学习路径 `/path`、单词默写 `/spelling`、词库 `/bank`、背诵 `/recitations`、收藏 `/collections`） + 工具（导入素材 `/import`、词典扫描 `/dict-ingest`、设置 `/settings`）。
- **不新增路由**；`/reader/:id` 需 id，不进侧栏（从素材/收藏进入）。
- **必要性**：PC 不能用底部 Tab（任务书明确禁止简单拉伸小程序/移动页）。

### 3.3 新增 `src/components/layout/DesktopTopBar.tsx`（新文件）
- 左：品牌 + 折叠按钮；中：全局搜索**触发入口**；右：账号（→ `/profile`）、设置（→ `/settings`）。
- **复用 SearchDock 的 overlay**，不重写 385 行搜索逻辑（见 3.4）。

### 3.4 改造 `src/components/layout/SearchDock.tsx`（小改，非重写）
- 现状：入口行 + `createPortal` 全屏 overlay（`fixed inset-x-0 top-0 z-50`），`openOverlay()` 为内部函数。
- 改动：给组件加**可选** `variant?: 'dock' | 'topbar'`（默认 `'dock'`，行为与今天完全一致）：
  - `'dock'`：渲染现有底部入口行（移动档用）。
  - `'topbar'`：渲染适合顶栏的紧凑入口（桌面档用），**overlay 逻辑原样复用**。
- overlay 内层容器在桌面档加 `mx-auto max-w-[720px]`，避免 1920px 下结果列表被拉成超宽行。
- **必要性**：搜索逻辑（防抖 300ms、竞态序号、历史=访问记录、输入法 isComposing 判定、Esc 收起）极其精细，**重写必然退化**；只加一个 variant 是最小改动。
- **风险**：本文件当前干净，但属并行任务高频区（前提卡记忆已标注）→ 实施前必须重新 `git status` 复核。

### 3.5 改造 `src/components/layout/AppShell.tsx`（分支，非破坏）
- 现状：`app-frame` + `main` + 底部 sticky 停靠组 + Sync 组件。
- 改动：
  ```tsx
  const isDesktop = useIsDesktop()
  if (isDesktop) {
    return (
      <div className="flex min-h-screen">            {/* 不用 .app-frame */}
        <SideNav />
        <div className="flex min-w-0 flex-1 flex-col">
          <DesktopTopBar />
          <main className="flex-1 overflow-y-auto">{children}</main>
        </div>
        <SyncIndicator /><SyncNotice />
      </div>
    )
  }
  return (/* 现有结构，保持原样 */)
  ```
- **必要性**：`AppShell` 是 19 条路由的公共外壳，在此分支即可让全部页面一次性获得桌面布局，是最省改动的切入点。
- **关键收益**：桌面分支**不使用 `.app-frame`** → 无需改动占用中的 `index.css`，移动端分支逐字不变。
- `showGlobalSearch` 语义保留：`/search` 页桌面顶栏同样不显示搜索入口（避免重复）。
- `SyncIndicator / SyncNotice` 两档都保留（本期同步是桩，但角标是既有 UI，不擅自删）。

### 3.6 `src/index.css` —— **本期不改**
- `.app-frame` 的 375px 对移动档仍然生效（桌面档根本不套这个类），因此**无需任何覆盖**。
- 该文件正被并行 Agent 改动（`M src/index.css`）→ 主动回避，零冲突。
- 若确需桌面专属样式（侧栏滚动条等），写在**新文件**里由 `SideNav`/`DesktopTopBar` 自己 import，或直接用 Tailwind 工具类。

### 3.7 `src/components/layout/BottomTabBar.tsx` —— **不改**
- 桌面档由 AppShell 分支决定不渲染它，组件本身保持原样；`TABS` 常量被 `SideNav` 复用（若需导出则改为具名导出，**加导出不改逻辑**）。

### 3.8 `src/App.tsx` —— **不改**
- 路由结构不变；桌面/移动是 `AppShell` 内部的事，19 条路由无需逐条改。
- `/reader/:id`、`/word/:word` 继续不套 AppShell（沉浸式），另按 §5 处理。

## 6. 六档宽度验收标准（任务书 §六.2）

| 宽度 | 档 | 验收项 |
|---|---|---|
| **1920** | D | 侧栏展开 240px；内容 `max-w-1200` 居中不拉满；搜索 overlay 内层限宽 720；无横向滚动 |
| **1440** | D | 同上；表格/长列表有横向滚动或自适应，不溢出视口 |
| **1366** | D | 侧栏+内容并排正常，内容不被侧栏遮挡；弹窗/下拉菜单不出可视区 |
| **1024** | D（临界） | 恰好切到桌面档；侧栏 240 + 内容 ≥ 700px 可用；无横向滚动 |
| **768** | M | **与改造前逐像素一致**：375px 居中框 + 底部 Tab + 底部 SearchDock；无横向滚动 |
| **390** | M | 同上，移动端零退化（回归红线） |

**通用检查项**：`document.documentElement.scrollWidth <= innerWidth`（无无意义横向滚动）；图标按钮带 `aria-label`/`title`；深色模式可读；空态仍用 `EmptyState`；`375px` 下不横向溢出（前提卡自查清单）。

**验证手段**：新增 `scripts/check_responsive_layout.mjs`（puppeteer-core + 本机 Edge，沿用项目既有 check 脚本风格），在 6 档宽度下跑真实浏览器截图 + 上述断言，输出**真实通过/失败清单**（任务书要求保留真实输出）。

## 12. 补审三：1024px 临界宽度（真实浏览器实测）

**方法**：在仓库外的临时目录复刻提议的桌面外壳几何（侧栏 240／折叠 64、顶栏 56、内容 `max-w-1200`、含 720px 最小宽表格），用本机 Edge（puppeteer-core）在 4 档宽度实测。**未改动项目任何文件**。

| 视口 | 侧栏态 | 侧栏宽 | 顶栏高 | 内容盒宽 | 可用内容宽 | scrollWidth | 横向溢出 | 表格需横滚 |
|---|---|---|---|---|---|---|---|---|
| 1024 | 展开 240 | 240 | 56 | 784 | **736** | 1024 | **否** | 否 |
| 1024 | 折叠 64 | 64 | 56 | 960 | 912 | 1024 | 否 | 否 |
| 1366 | 展开 240 | 240 | 56 | 1126 | 1078 | 1366 | 否 | 否 |
| 1366 | 折叠 64 | 64 | 56 | 1200 | 1152 | 1366 | 否 | 否 |
| 1440 | 展开 240 | 240 | 56 | 1200 | 1152 | 1440 | 否 | 否 |
| 1920 | 展开 240 | 240 | 56 | 1200 | 1152 | 1920 | 否 | 否 |

**结论（实测，非凭感觉）**：1024px 下侧栏**展开 240px 完全够用** —— 可用内容宽 736px，`scrollWidth == 1024` 无横向溢出，连 720px 最小宽的表格都无需横滚。
→ **侧栏默认展开**；折叠做**用户偏好开关**（可持久化），不作为 1024px 的必需降级。

> 局限声明：以上为几何原型实测，非真实应用；A5 落地后须用真实应用在 1024px 复测（A8）。

## 13. 补审四：认证占位边界（硬性）

本期**不接后端、不做跨设备登录同步、不修改 Dexie 数据结构**。

| 允许 | 禁止 |
|---|---|
| 声明 `AuthMode = 'stub' \| 'remote'` 开关（默认 `stub`） | ❌ 接入任何"假认证"实现、伪造登录成功 |
| 预留 `RemoteAuthClient` **接口声明**（无实现） | ❌ 引入无实际作用的复杂认证抽象（全套 OAuth/OIDC/会话中间件骨架） |
| `/auth/callback` 占位页，**明示"当前不支持"** | ❌ 该页自动模拟登录、自动写 session、自动跳转"已登录" |
| `AccountSection` 在 stub 态显式标注「本地模式 · 跨设备同步暂不支持」 | ❌ 显示"已同步""云端已备份"等不实状态 |
| 文档化令牌红线（不进 localStorage / URL） | ❌ 自动制造任何跨设备同步能力 |

**红线对齐**：与既有红线一致——「在线翻译未接入就是未接入」「SRS 交接失败如实报待重试、不显示已同步」。认证同理：**未接入就是未接入**。
