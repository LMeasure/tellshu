## 1. 两个 Bug 的根因

### Bug 1：学习进度无法持久化 —— 根因是「压根没有持久化」

| 证据 | 位置 |
|---|---|
| 进度全在 React 内存态 | `LearningFlow.tsx:56-57`（`batchIdx` / `idx` 两个 `useState`） |
| 队列是现场切分、从不落库 | `LearningFlow.tsx:89-96`（`useMemo` 从内存数组切片） |
| **进入页面即无条件归零** | `LearningFlow.tsx:85-87` `useEffect(() => setIdx(0), [batchIdx, bookParam, levelParam])` |
| 索引没有夹紧 → 可能渲染空白卡 | `LearningFlow.tsx:112-116` + `173`（`{current && <WordCard/>}`） |
| 唯一「已学完」记录 = 结算时加生词本，中途退出什么都不留 | `finishRound()` + `addManyToVocab` |

结论：不是「恢复逻辑写错」，是**没有任何恢复逻辑**。退出 / 刷新 / 重进 / 重登录一律从第 1 组第 1 张开始；已学过的词因为从来没被记录，必然又排在最前面。

### Bug 2：单词释义不显示 —— 本页不查词典，数据是全的，坏在渲染层

先更正三条想当然的猜测（都有实测数据支撑）：

| 猜测 | 实测结论 |
|---|---|
| 词典查询失败 / 关联 key 错 | ❌ 本页释义**直接取词包字段** `ContentWord.definition_zh`，不存在词典查询链路（只有 `/word/:word` 与扫描词典库才查） |
| 数据缺释义 | ❌ 全库 22,791 条里**缺中文释义仅 5 条**（`check` / `spot` 等） |
| 只取了第一条记录 | ❌ 没有「取第一条」的查询逻辑（因为是字段直读） |

真实问题在 `src/components/learning/WordCard.tsx:32-33、115-117`：

1. **单开关门控 + 无兜底**：释义整段被 `settings.chineseAssist` 门控；关闭后整段消失。而 `definition_en` 在这些词包里 **100% 为 null**（实测 0 条非空）→ 关掉就是纯空白。浏览器实测复现：开关关闭后释义段落与提示一并消失（设置项原文「关闭则不显示中文释义」）。
2. **多词性 / 多义项被压成一行**：`by` 的真实释义是 `prep. 在...旁边；通过（某种方式）；…；adv. 经过；附近；搁置`，旧代码整串塞进一个 `<p>`。**全库 20,412 条（89.6%）含多个义项**，也就是说绝大多数词的释义在旧页面上都是一坨不换行的文本。项目里已有的结构化工具 `parseDefinitionZh` + `bindExamples`（`src/lib/wordSense.ts`）**只有 WordDetail 用了，WordCard 没用**。
3. **无加载 / 错误态**：进度持久化后要靠 id 回查词包，不做状态就会出现「词回来了、释义还没回来」的空白窗口。

## 3. 学习进度持久化方案（Bug 1 修复）

**存什么**：一个「词本 × 难度档」一份文档（主键 `CET4::all` / `CET6::2`），整份 `put()` 覆盖写——与 `spellingSession.ts` 同口径（`TableService` 没有事务 API，单文档一次 put 才能保证「顺序 + 位置 + 完成态」同生共死）。

```
WordLearningSession {
  id / book / level
  queue:      string[]   // 完整有序队列（只存稳定词 id，不存内容）
  position:   number     // 队列下标，指向当前词
  completed:  string[]   // 已完成（已推进过）的词 id，去重集合
  batch_size / created_at / updated_at / owner / gesture_hinted?
}
```

**为什么只存 id**：释义 / 例句 / 词源按 id 从词包回查。不把 5MB 内容复制进库，也避免库里内容与词包版本漂移；恢复时「词和释义一起回来」，不会出现只有词没有释义。

**四条关键规则**

1. **进入页面 ≠ 重新开始**：位置一律从库里读，没有任何 `setPosition(0)` 的副作用路径。
2. **前进 = 标记当前词完成 + 位置 +1；后退只回退位置、不动完成态**（回去看已学过的词，不该把它的完成标记清掉）。重复进出同一个词不会重复计数（幂等）。
3. **新建队列时把已在生词本里的词标为已完成**，位置落在第一个没学过的词上（本次用户拍板）→ 已完成的词不会无故重新出现在学习路径最前面；它们仍留在队列里，右滑可回看。
4. **重学是唯一会清进度的路径**，且必须走确认弹窗（「只重学本组」/「从整本第一词重学」），绝不把普通进入解释成重学。

**边界与自愈**：到头 / 到底返回同一对象引用（调用方据此判断「没切换」）；库里文档异常（position 越界、`batch_size` 非法、队列有重复或失效 id）载入时自动校正；词包换版时失效 id 剔除、新词追加到队尾、位置按**锚点词 id** 重新定位（绝不回退到 0）。

**是否需要数据库迁移**：需要，且已做。原因是学习会话是「一词本一份文档」的行级实体，与 `vocab` / `reviewLog` 同类，塞进账号设置行会与设置、同步队列混在一起；新增 Dexie `version(11)` 是纯追加，存量库平滑升级（升级验证见 8.2）。

## 4. 词典释义修复方案（Bug 2 修复）

1. **结构化渲染**：`WordCard` 改用 `parseDefinitionZh()`（详情页同款纯函数）切分后，按「词性斜体灰固定列 + 该词性下逐条释义」展示，**一个义项都不丢**；无词性标注的词回退为单组、用词条的 `pos` 兜底。例句 / 词根词缀 / 词源 / 知识网络全部保留原样。
2. **不再空白**：关掉「中文辅助」时先尝试英文释义；英文也没有（本词包全为空）就显示「已按设置隐藏中文释义（设置里可重新打开）。」；数据本身缺释义则显示「该词暂未收录释义。」。
3. **加载 / 错误态**：词包未到位时渲染骨架 + 「正在读取学习进度…」；加载失败走 `ErrorState` 并给「重试」；队列里的 id 若在词包中查不到，剔除但不占位（不出现空白卡）。
4. **没有动任何词典数据**：不新增、不改写、不删除词条，也不新造一套词典。

实测（`by`）：2 个词性分组、7 条义项、首末义项都在页面上。

## 5. 左右滑动的实现方式

`src/hooks/useSwipeSwitch.ts`，容器加 `touch-action: pan-y`（Tailwind `touch-pan-y`）：

| 机制 | 取值 / 规则 |
|---|---|
| 事件 | Pointer Events（touch / mouse / pen 统一），真实拖拽轨迹，非点击模拟 |
| 轴向锁定 | 位移 ≥ 10px 时按 `|dx| > |dy| × 1.3` 锁定一次；锁纵向则本次手势彻底放手给页面滚动 |
| 阈值 | `max(56px, 容器宽 × 14%)`，且手势时长 ≤ 1.5s |
| 跟手反馈 | 手指位移 × 0.35 阻尼，直接改 DOM `transform`（不走 React state，避免每帧重渲染） |
| 防连发 | 单次手势最多触发一次 + 切换冷却 180ms + `sessionRef` 同步取值（不会读到旧闭包） |
| 边界 | 首张右滑 / 末张左滑：位置不动，给一行轻提示（「已经是第一个词了」），卡片始终有内容 |
| 组内最后一张 | 左滑 = 结算本轮（等价原来的「完成本轮」），不越界、不空白 |
| PC | 鼠标拖拽同一条链路；另支持键盘 ← / → |
| 动画 | 进场 220ms 位移淡入，`prefers-reduced-motion` 下直接换卡 |

## 6. 页面自适应的实现方式

1. 移除页面根 `min-h-screen` 与卡片外层 `flex-1` —— 这两处是在 AppShell 已有滚动区 + 底部停靠组之上又强撑一屏的根源（旧版实测：390×844 下文档高 985px / 视口 844px，卡片下方固定留 78px 空白）。
2. 内容自然流：高度 = 内容 + 底部导航，多一点也不撑。实测三视口「多余空白 = 0px」。
3. 内容超高时正常滚动，卡片不用 `overflow:hidden`、不限高（实测 `overflow: visible`，词源 149 字完整可见）。
4. 滚到底后内容底边与导航顶边重合（375×667：612/612；390×844：789/789；1280×800：745/745）—— 不被遮挡、不互相覆盖。
5. 底部控件：`/learn` 传 `showGlobalSearch={false}` 摘掉「搜单词…」入口行；删除「上一张 / 下一张」；保留一个**组内最后一张才出现**的「完成本轮 / 学完了」（不是翻页按钮，是 SRS 交接入口）与顶栏「重新学习」。

## 9. 尚未解决的问题与风险

1. **PC 仍是 375px 手机框居中**（`app-frame max-w-app`），两侧大留白。这是项目既有的移动端优先设计，本次按「保持现有视觉风格」未动；若要做桌面端自适应，属于并行任务「多端兼容改造」的范围，需单独排期。

### 12.2 一个被发现的真实回归 & 修复（关键）

引入点词查词后浏览器实测发现：**在学习卡里点击单词按钮打不开查词弹窗**（`check_word_click_lookup.mjs` L3 失败），但 JSDOM 单测通过。根因是 `useSwipeSwitch` 在 `onDown` 里**立即**对容器 `el.setPointerCapture(pointerId)`——纯点按也被容器抢走指针，导致子按钮的 `click` 被派发到容器而非按钮，`onClick` 永不触发。

修复（改 `src/hooks/useSwipeSwitch.ts`，**共享 hook**，LearningFlow 与 Reader 共用）：把 `setPointerCapture` 从 `onDown` 移到 `onMove`，且**仅在轴向锁定为横向滑动的瞬间**才捕获。纯点按（无位移）不再捕获 → 子元素 `click` 正常触发（点词查词可用）；真实横滑仍会在移动中捕获 → 跟手位移不受影响。同时撤掉按钮上的 `onPointerDownCapture` 兜底（否则会挡住「从单词上起手滑动」的手势，导致主验收 C6 连滑失败）。

修复后两类验收同时全绿：主验收 **70/70**（C6 连滑恢复），聚焦验收 **7/7**（点词弹窗 + 查看详情跳转）。

> `useSwipeSwitch` 为共享 hook；本次仅移动 `setPointerCapture` 时机，API 与轴向锁定 / 阈值 / 冷却等判定逻辑一行未变，Reader 翻页滑动向后兼容（已通过 `tsc` + 全量单测 + `/learn` 主浏览器 70/70；Reader 专项浏览器验收不在本轮范围，但 hook 行为不变）。

## 15. 述树单词学习页｜剩余问题修复与验收（2026-11-01 续）

### 15.1 任务 A：PC 端（1280px）三个失败的真实根因与修复

**复现**：重跑 `scripts/check_word_learning_browser.mjs`，`D-pc1280-1/4/5` 三项失败。
**DOM 实测（puppeteer 量 1280×800 的 /learn）**：`matchDesktop=true`、`hasHscreen=true`、`hasAppFrame=false` → AppShell 走**桌面分支**（SideNav + DesktopTopBar + `main` 内部滚动；**不渲染 BottomTabBar**）。关键事实：
- `document.querySelector('nav')` 在桌面档只命中**左侧 SideNav 的 `<nav>`**（top=56、高=744），**根本没有底部导航**。
- 测试原口径把 `scrollHeight = 内容 + 底部导航` 当成公式，在 `h-screen` + 内部滚动的桌面壳下永远不成立（被测量的「nav」是侧栏，不是底栏）。

#### 根因一（真实 Bug，D-pc1280-1）
`/learn` 用 `<AppShell showGlobalSearch={false}>`（App.tsx:55）。移动分支用 `showGlobalSearch` 门控 `SearchDock`，但**桌面分支的 `DesktopTopBar` 无条件渲染 `<SearchDock variant="topbar" />`**（其按钮 `title="搜单词"`），忽略该 flag。故桌面档学习页仍显示全局搜索框。

#### 根因二 / 三（测试口径与桌面壳不匹配，非真实布局缺陷，D-pc1280-4/5）
桌面壳**无底部导航**，原「内容底 ≤ 底栏 top」「scrollHeight=内容+底栏」的断言量到的是左侧 SideNav，公式在 `h-screen` 锁视口下恒为负（实测 `scrollHeight=800`、内容 673、SideNav 744 → 多余空白=-617）。内容 673 落在 744 的主区内、无遮挡、无强制空白——属自然的「内容比视口矮」留白，非缺陷。

#### 修复
- `src/components/layout/AppShell.tsx`：桌面分支 `<DesktopTopBar showSearch={showGlobalSearch} />`。
- `src/components/layout/DesktopTopBar.tsx`：签名加 `showSearch?: boolean`（默认 true），仅当 `showSearch` 为真时渲染中部 `<SearchDock variant="topbar" />`。效果：学习页（`showGlobalSearch=false`）桌面/移动均不显示搜索框；其余页面（默认 true）搜索照常——**未影响其他页面搜索功能**。
- `scripts/check_word_learning_browser.mjs`：D-pc1280-4/5 改为桌面档真实不变量（移动档 m375/m390 原断言一字未动）：
  - 4 = 内容在自身滚动容器内可滚到底（`main.scrollTop+clientHeight ≥ scrollHeight-2`）且**不存在 `border-t` 样式的底部导航**（BottomTabBar 特征）→ 桌面档 `reachable=true bottomNav=false`。
  - 5 = 外壳锁定视口高（`document.scrollHeight - innerHeight ≤ 2`）→ 桌面档实测 `0px`。
- 同步为 `EntryDetailCard` / `StudyNotePanel` 的例句中文补 `data-testid="example-zh"`（本轮上一轮已加，此轮确认保留），统一可测。
