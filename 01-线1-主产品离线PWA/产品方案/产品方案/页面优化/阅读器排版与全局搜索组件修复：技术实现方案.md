
## 一、总体实现原则

本次改造分为两个模块：阅读器排版修复、全局搜索组件修复。核心不是单纯调整 CSS，而是同时修正可用高度计算、滚动容器布局、键盘状态管理、搜索结果排序与滚动定位。

建议遵循以下原则：

1. 高度统一：页面外层使用 `100dvh`，阅读区和搜索面板分别管理自身的可用空间。
2. 内容完整：阅读器以完整行或完整排版单元分页，不能通过 `overflow: hidden` 掩盖分页错误。
3. 状态驱动：搜索防抖、键盘显示、Tab 栏显隐由明确的状态和事件控制。
4. 排序与布局分离：搜索结果的数据顺序、视觉顺序、滚动位置分别定义，避免反复反转数组导致顺序错误。
5. 兼容移动端：优先使用标准浏览器能力，并对 iOS Safari、Android 浏览器及 PWA 环境进行实际验证。

以下是建议的技术设计。由于目前没有提供项目源码，文件路径、现有框架和组件名称需要在实施前核对；以下代码是可供开发人员落地的参考实现，不代表已经在现有项目中验证。

# 模块一：阅读器排版与 UI 修复

## 1.1 紧急修复：分页高度计算，彻底避免吃字

### 问题根因

平滑模式或覆盖模式中，分页算法可能按整个阅读容器的高度计算分页，却没有扣除底部导航栏占用的空间。

例如：

- 阅读区域高度：700px
- 底部导航栏高度：64px
- 实际可用于正文的高度：636px

如果算法仍然按照 700px 排版，最后一行可能延伸到导航栏后方，导致文字被遮挡或裁切。

### 正确的高度计算

示例：阅读区域可用高度

阅读容器高度

## 700px

底部导航栏

### 64px

正文可用高度

## 636px

实际计算还需要扣除正文上下内边距、顶部工具栏、页码区等占用空间，避免重复扣除同一部分。

统一定义：

\\[ H\_{\text{正文}}=H\_{\text{容器}}-H\_{\text{顶部}}-H\_{\text{底部}}-P\_{\text{上下}} \\]

其中：

- \\(H\_{\text{容器}}\\)：实际阅读容器高度。
- \\(H\_{\text{顶部}}\\)：占据布局空间的顶部工具栏高度。
- \\(H\_{\text{底部}}\\)：底部导航栏或其他固定底栏占用的高度。
- \\(P\_{\text{上下}}\\)：正文区域上下内边距之和。

重要： 如果导航栏已经通过正常文档流占用了空间，或者阅读容器的高度已经排除了导航栏，就不能再次扣减。应以实际 DOM 布局为准，防止重复计算。

### 推荐实现

```
.reader-page {
  height: 100dvh;
  min-height: 0;
  display: flex;
  flex-direction: column;
  overflow: hidden;
}

.reader-header {
  flex: 0 0 auto;
}

.reader-content {
  flex: 1 1 auto;
  min-height: 0;
  box-sizing: border-box;
}

.reader-bottom-nav {
  flex: 0 0 var(--reader-nav-height);
  height: var(--reader-nav-height);
}
```

```
:root {
  --reader-nav-height: 64px;
}
```

如果项目采用底部绝对定位的导航栏，正文区域必须显式扣除它占用的空间。例如：

```
.reader-content {
  height: calc(
    100dvh
    - var(--reader-header-height)
    - var(--reader-nav-height)
  );
  box-sizing: border-box;
}
```

这里的 `--reader-header-height` 需要按实际项目设置，不能直接假设所有设备的顶部栏高度都相同。

### 分页算法的关键要求

分页不能仅仅判断“字符是否超出高度”，而要判断下一个完整排版单元是否能放入当前页。

建议实现流程：

1. 测量正文容器的实际可用高度。
2. 按当前字体、字号、行高、字间距和内容宽度完成排版测量。
3. 根据完整行的实际高度，累加计算当前页已占用高度。
4. 如果下一整行放入后会超出可用高度，则将该行完整移至下一页。
5. 如果一段文字本身超出一页，允许在段落内部按完整行分割，但不允许从单行中间截断文字。
6. 字号、屏幕方向、窗口尺寸或字体加载状态改变后，重新测量并生成分页结果。

示例伪代码：

```
function paginateLines(lines, availableHeight) {
  const pages = [];
  let page = [];
  let usedHeight = 0;

  for (const line of lines) {
    const lineHeight = line.height;

    if (
      page.length > 0 &&
      usedHeight + lineHeight > availableHeight
    ) {
      pages.push(page);
      page = [];
      usedHeight = 0;
    }

    page.push(line);
    usedHeight += lineHeight;
  }

  if (page.length > 0) {
    pages.push(page);
  }

  return pages;
}
```

这段代码假设 `lines` 已经是经过正确换行的完整行，且每行的 `height` 是实际测量值。

它不是完整的中文排版引擎。真实项目还需要处理段前段后距、图片、标题、注释、特殊字符以及跨段落分页等情况。

需要避免的做法：

- 用固定字符数估算一行高度。
- 用 `line-height × 固定行数` 代替实际排版测量，却不处理特殊内容。
- 在超出时直接对正文容器应用 `overflow: hidden`，然后认为分页已修复。
- 在分页过程中直接截取 DOM 文本节点，破坏原有内容结构。

### 验收标准

- 最后一行文字不会进入底部导航栏区域。
- 每页末尾不会出现半行文字。
- 连续翻页时没有文字丢失、重复或顺序错乱。
- 改变字号、行距、屏幕尺寸后，分页结果正确重算。
- 长段落、标题、图片及特殊字符均通过测试。

## 1.2 上下滑动模式：底部增加安全留白

上下滑动模式不需要分页，但必须确保最后一行能够滚动到导航栏上方。

推荐使用正常布局，而不是让正文和导航栏相互覆盖。

```
.reader-scroll {
  height: 100%;
  min-height: 0;
  overflow-y: auto;
  overflow-x: hidden;
  box-sizing: border-box;

  padding-bottom: calc(
    var(--reader-nav-height)
    + env(safe-area-inset-bottom, 0px)
  );

  scrollbar-width: none;
  -ms-overflow-style: none;
}

.reader-scroll::-webkit-scrollbar {
  display: none;
}
```

如果导航栏已经通过正常文档流占用空间，正文不需要再次添加完整的导航栏高度，只需要补足实际缺少的底部安全留白。

对于 iPhone 等带有底部安全区的设备，需要区分：

- 导航栏本身的高度。
- 设备底部安全区的高度。
- 阅读正文是否已经包含安全区的留白。

三者不能重复叠加。

## 1.3 全屏适配：外层容器强制使用 `100dvh`

建议将阅读器页面根节点统一为：

```
.reader-page {
  height: 100vh;   /* 兼容旧浏览器的回退 */
  height: 100dvh;
  width: 100%;
  min-height: 0;

  display: flex;
  flex-direction: column;
  overflow: hidden;
  box-sizing: border-box;
}
```

`100dvh` 是动态视口高度，能够更好地反映移动浏览器地址栏展开或收起时的可视区域变化。

但仅仅设置 `100dvh` 并不能保证内部布局正确。还需要检查：

- 所有需要伸缩的 flex 子项是否设置 `min-height: 0`。
- 是否存在子元素额外设置 `height: 100vh`。
- 是否有固定定位元素超出视口。
- 是否存在父容器 `overflow: hidden` 导致可滚动区域被截断。
- 是否把导航栏高度同时算进正文高度和父容器高度。

## 1.4 隐藏阅读区滚动条

推荐组合：

```
.reader-scroll {
  overflow-y: auto;
  overflow-x: hidden;
  scrollbar-width: none;
  -ms-overflow-style: none;
}

.reader-scroll::-webkit-scrollbar {
  display: none;
}
```

说明：

- `scrollbar-width: none`：Firefox。
- `::-webkit-scrollbar`：Chrome、Safari 及部分移动浏览器。
- `overflow-y: auto`：保留正常滚动能力。
- 不要为了隐藏滚动条改成 `overflow: hidden`，否则会连滚动功能一起关闭。

# 模块二：全局搜索组件修复

## 2.1 核心交互流程

搜索组件建议使用明确的状态机，避免输入框、结果列表、软键盘和 Tab 栏各自维护互相冲突的状态。

用户输入任意字符

300ms 防抖

新输入会取消旧的待执行查询

查询与匹配度排序

最高匹配度 → 最低匹配度

视觉反序排列

最低匹配度在上，最高匹配度在输入框旁

具体约定：

- 输入后等待 300ms 再查询。
- 每次新输入都取消上一次防抖任务。
- 如果查询支持异步请求，使用请求序号或取消机制，防止旧请求覆盖新结果。
- 回车进入全页搜索；如果 IME 正在组合中文输入，不应误触发。
- 点击搜索结果进入详情。
- 点击「查看全部」进入全页搜索。
- 结果为空时展示空状态，而不是保留上一轮结果。
- 清空输入后，根据现有产品规则展示最近搜索或默认内容。

## 2.2 如何实现结果反序排列并贴底对齐？

这是本次搜索组件修复的核心。

需要区分两个概念：

- 反序排列：视觉上，最高匹配度结果位于列表底部。
- 贴底对齐：结果不足以填满面板时，结果整体仍然位于底部，而不是堆在顶部。

建议使用以下 DOM 结构：

```
<div class="search-overlay">
  <div class="search-panel">
    <div class="search-results">
      <div class="search-results-inner">
        <!-- 最低匹配度 -->
        <div class="search-result">结果 C</div>
        <div class="search-result">结果 B</div>
        <!-- 最高匹配度 -->
        <div class="search-result">结果 A</div>
      </div>
    </div>

    <div class="search-input-area">
      <input class="search-input" />
    </div>
  </div>
</div>
```

这里最重要的是：输入框在结果列表后面，结果容器本身占据剩余空间。

推荐 CSS：

```
.search-overlay {
  position: fixed;
  inset: 0;
  height: 100vh;
  height: 100dvh;
  width: 100%;

  display: flex;
  flex-direction: column;
  overflow: hidden;
  box-sizing: border-box;
}

.search-panel {
  flex: 1;
  min-height: 0;

  display: flex;
  flex-direction: column;
  overflow: hidden;
}

.search-results {
  flex: 1 1 auto;
  min-height: 0;
  overflow-y: auto;
  overflow-x: hidden;

  display: flex;
  flex-direction: column;
  justify-content: flex-end;

  scrollbar-width: none;
  -ms-overflow-style: none;
}

.search-results::-webkit-scrollbar {
  display: none;
}

.search-results-inner {
  flex: 0 0 auto;
  display: flex;
  flex-direction: column;
  justify-content: flex-end;
}

.search-input-area {
  flex: 0 0 auto;
  position: relative;
  z-index: 2;
}

.search-input {
  width: 100%;
  box-sizing: border-box;
  outline: none;
  border: none;
}
```

### 为什么需要 `search-results-inner`？

仅给外层设置 `justify-content: flex-end`，在某些内容溢出和滚动场景下，可能出现滚动起点不符合预期的问题。

增加内层内容容器后：

- 外层 `.search-results` 负责滚动。
- 内层 `.search-results-inner` 负责内容的底部对齐。
- 当结果很少时，整个结果组向底部靠拢。
- 当结果很多时，内容自然超出容器，可以滚动查看。

这里使用 `flex: 0 0 auto`，避免内层容器被压缩到容器高度，从而让超出内容保留正常的滚动范围。

### 数据排序建议

不要同时对数据数组反转两次。建议统一约定：

```
const sortedResults = [...results].sort(
  (a, b) => a.score - b.score
);
```

然后按数组顺序直接渲染。

这里假设 `score` 越大，匹配度越高，因此升序排序后：

```
顶部
  结果 C：匹配度 0.30
  结果 B：匹配度 0.60
  结果 A：匹配度 0.95
底部（紧贴输入框）
```

若实际搜索服务返回的匹配度分值定义相反，则需要调整排序方向。不要仅凭字段名称猜测分数语义。

如果需要稳定排序，分数相同时应保留原始顺序或使用明确的次级排序规则。

## 2.3 如何监听键盘并处理 Tab 栏遮挡？

### 先明确移动端的实际行为

移动端软键盘不是一个普通的 DOM 元素。不同浏览器对视口变化的处理不同：

- 部分浏览器会缩小布局视口。
- 部分浏览器主要改变视觉视口。
- iOS Safari、Android Chrome、PWA 的表现可能不同。

因此，不建议只依赖 `window.innerHeight`，也不建议只监听 `focus` 就认定键盘已经完全弹起。

### 推荐方案：Visual Viewport API + 焦点状态

```
function observeKeyboard(
  onChange: (visible: boolean, height: number) => void
) {
  const viewport = window.visualViewport;

  if (!viewport) {
    return () => {};
  }

  const update = () => {
    const height = Math.max(
      0,
      window.innerHeight - viewport.height - viewport.offsetTop
    );

    const visible = height > 120;

    onChange(visible, height);
  };

  viewport.addEventListener("resize", update);
  viewport.addEventListener("scroll", update);
  update();

  return () => {
    viewport.removeEventListener("resize", update);
    viewport.removeEventListener("scroll", update);
  };
}
```

这是一种实用的初始估算方式，不是所有设备都适用的精确键盘测量公式。某些浏览器会同时改变 `innerHeight` 与 `visualViewport.height`，因此正式实现前需要在目标设备上验证。

### Tab 栏处理

当搜索框获得焦点且键盘弹起时：

1. 搜索层保持全屏定位。
2. 结果列表缩小到键盘上方的可用高度。
3. 底部 Tab 栏隐藏，或确保其被搜索层完全覆盖。
4. 搜索输入框贴在搜索面板底部，也就是键盘上沿。
5. 键盘收起后恢复正常 Tab 栏显示。

可以通过状态控制：

```
<div className={keyboardVisible ? "app keyboard-open" : "app"}>
  <main className="app-content">
    {/* 页面内容 */}
  </main>

  <nav className="bottom-tab-bar">
    {/* 底部 Tab */}
  </nav>

  {searchOpen && <SearchOverlay />}
</div>
```

```
.app {
  height: 100vh;
  height: 100dvh;
  display: flex;
  flex-direction: column;
  min-height: 0;
  overflow: hidden;
}

.app-content {
  flex: 1 1 auto;
  min-height: 0;
}

.bottom-tab-bar {
  flex: 0 0 auto;
}

.app.keyboard-open .bottom-tab-bar {
  display: none;
}

.search-overlay {
  position: fixed;
  inset: 0;
  height: 100vh;
  height: 100dvh;
  z-index: 1000;
}
```

如果搜索覆盖层的 `z-index` 高于 Tab 栏，即使 Tab 栏没有设置 `display: none`，也可以将它覆盖。但明确隐藏 Tab 栏能减少布局冲突，并避免它在搜索层关闭时短暂闪现。

### 更稳妥的增强

对于支持 Visual Viewport API 的浏览器，可以把实际可视高度同步到 CSS 变量，再用于调整搜索层。

```
function syncVisualViewport() {
  const viewport = window.visualViewport;

  if (!viewport) return;

  document.documentElement.style.setProperty(
    "--visual-height",
    `${viewport.height}px`
  );
}
```

```
.search-overlay {
  height: var(--visual-height, 100dvh);
}
```

需要注意，`viewport.height` 与 `viewport.offsetTop` 在某些场景下都可能变化。如果搜索层使用 `position: fixed`，还要根据目标浏览器验证定位基准，不能只同步高度就假设所有键盘遮挡问题已经解决。

此外，必须在组件卸载时移除事件监听器，防止重复注册和内存泄漏。

## 2.4 搜索框无感聚焦：去掉绿框和边框

如果要求聚焦时不出现绿色边框，建议明确覆盖输入框、搜索框外层以及浏览器焦点样式。

```
.search-input,
.search-input:focus,
.search-input:focus-visible {
  outline: none;
  border: none;
  box-shadow: none;
}
```

如果绿色边框来自外层容器：

```
.search-input-wrapper,
.search-input-wrapper:focus-within {
  outline: none;
  border-color: transparent;
  box-shadow: none;
}
```

如果项目使用 Tailwind CSS，可在对应输入框上使用：

```
border-0 outline-none ring-0 focus:border-0
focus:outline-none focus:ring-0 focus-visible:ring-0
```

注意： 视觉上无感聚焦不等于应该取消所有可访问性反馈。对于键盘用户，建议保留一种低干扰的焦点提示，例如轻微背景变化或不显眼的边框颜色，而不是完全无法判断当前焦点所在。

# 三、搜索逻辑实现细节

## 3.1 300ms 防抖与过期请求保护

防抖只能减少请求数量，不能单独解决异步请求返回顺序错误的问题。

例如：

1. 用户输入 `a`，发起请求 A。
2. 用户继续输入 `ab`，发起请求 B。
3. 请求 B 先返回，请求 A 后返回。
4. 如果没有过期请求保护，A 可能覆盖 B 的结果。

建议同时使用 `AbortController` 或递增请求序号。

参考实现：

```
let debounceTimer: ReturnType<typeof setTimeout> | undefined;
let requestController: AbortController | undefined;
let requestId = 0;

function onSearchInput(query: string) {
  clearTimeout(debounceTimer);

  debounceTimer = setTimeout(async () => {
    const currentId = ++requestId;

    requestController?.abort();
    requestController = new AbortController();

    try {
      const results = await searchBooks(query, {
        signal: requestController.signal,
      });

      if (currentId !== requestId) return;

      renderResults(results);
    } catch (error) {
      if (
        error instanceof DOMException &&
        error.name === "AbortError"
      ) {
        return;
      }

      throw error;
    }
  }, 300);
}
```

`searchBooks` 和 `renderResults` 是示意接口，需要接入项目已有的搜索服务与状态管理。

还需要补充：

- 组件卸载时清理定时器。
- 清空输入时立即取消旧请求并清空旧结果。
- 对空白字符进行规范化。
- 对查询失败显示明确的错误状态。

建议先修复阅读器，再处理搜索组件。阅读器的吃字属于内容完整性问题，应优先验证。

| 阅读器上下滑动模式   | 最后一行能完整滚动到导航栏上方         |

## 六、推荐实施顺序

1. 阶段 1：阅读器排版修复。 检查分页算法、导航栏高度来源、正文实际高度；修复完整行分页和底部留白。
2. 阶段 2：全屏布局修复。 统一 `100dvh`、`min-height: 0`、flex 子项及滚动容器规则。
3. 阶段 3：搜索结果布局。 先固定 DOM 顺序和匹配度排序，再实现 `justify-content: flex-end` 与独立滚动容器。
4. 阶段 4：软键盘适配。 接入 Visual Viewport 监听、Tab 栏状态控制和输入框贴底定位。
5. 阶段 5：搜索交互与视觉。 实现 300ms 防抖、请求过期保护、回车跳转、结果点击及隐藏滚动条。
6. 阶段 6：回归测试。 检查移动端键盘、短结果集、长结果集、字号变化和连续翻页。

最终需要重点把控的四点：

1. 分页高度必须以正文真正可用的高度为准，并按完整排版单元分页。
2. 键盘适配不能只靠 `focus` 事件，需要结合实际视口变化；Tab 栏隐藏与输入框定位必须协调。
3. 搜索结果的正确实现是“数据排序 + 视觉顺序 + 底部对齐 + 正常滚动”四者一致，而不只是反转数组。
4. 隐藏滚动条不能关闭滚动，无感聚焦不能破坏基本的键盘可访问性。

以上方案可以作为正式开发前的技术设计基线。实施前应先检查现有阅读器分页算法、搜索组件 DOM 结构及页面高度控制方式，再按上述方案做最小范围改造，避免在未知的现有布局上直接叠加 CSS。
