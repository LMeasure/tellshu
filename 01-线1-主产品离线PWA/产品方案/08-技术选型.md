# 技术选型（Tech Stack）v0.1 —「述树」零基础英语

> 前置：组件树 v0.1 已确认。本步在既定约束（React + Tailwind + shadcn/ui、375px 优先、本地 mock→Supabase/Firebase）下，补全运行时关键能力（TTS/ASR/AI/离线）与工程化方案，给出推荐项、备选与落地阶段。
>
> 目标：MVP 先把交互跑通（本地 mock），再无缝接云端与语音/AI 能力，不推翻已定架构。

## 0. 技术约束（用户既定，不可变）

| 约束 | 取值 |
|---|---|
| 前端框架 | React |
| 样式 | Tailwind CSS + shadcn/ui |

## 2. 前端工程化（推荐）

| 维度 | 推荐 | 备选 | 理由 |
|---|---|---|---|
| 构建 | **Vite + TypeScript** | Next.js | 纯客户端 Web App，Vite 启动快、包小；无需 SSR（内容本地化） |
| 包管理 | **pnpm** | npm/yarn | 快、省磁盘、严格依赖 |
| UI 库 | **Tailwind + shadcn/ui** | — | 既定约束；shadcn 基于 Radix，可访问性/深浅色/圆角开箱 |
| 路由 | **React Router v6** | TanStack Router | Tab + 嵌套路由成熟 |
| 状态 | **Zustand + persist** | Redux Toolkit | 轻量、无样板；persist 中间件直落本地，离线友好 |
| 表单 | **React Hook Form + Zod** | Formik | 校验轻、与 TS 友好 |
| 图标 | **lucide-react** | — | shadcn 默认搭配 |
| 测试 | **Vitest（单元）+ Playwright（e2e）** | Jest/Cypress | 与 Vite 同源、快 |
| 代码质量 | ESLint + Prettier + Husky | — | 提交门禁 |

**375px 适配规范**
- 根容器 `max-w-[375px] mx-auto`（或 `min-w` 约束），大屏居中留白。
- 采用 `rem`/Tailwind 间距；卡片圆角 `rounded-2xl`(16px)、强调用 `--accent`。
- 触摸目标 ≥44px；底部 Tab 固定 `safe-area-inset-bottom`。

## 3. 数据层：Mock → 本地 → 云端

### 3.1 三阶段落地
| 阶段 | 内容数据 | 用户/学习数据 | 社交数据 |
|---|---|---|---|
| Phase 0（纯 mock） | 本地 JSON（Linguabase 形状） | 内存/Zustand | mock 假数据 |
| Phase 1（本地持久化） | IndexedDB 缓存 | **IndexedDB（Dexie）** | mock 假数据 |
| Phase 2（云端） | CDN/对象存储增量 | Supabase 表 + 同步 | Supabase 真后端 |

### 3.2 本地存储
- **IndexedDB via Dexie**：承载**大数据量、需索引查询**的实体——`vocab / daily_plan / diagnose_result / favorite / collection / reading_time_aggregate / achievement`（06 中 `[本地]` 实体）。学习数据量大（生词本/复习队列）、需按 `next_review` 排程、按 `layer` 分组、按 `root` 聚合，IndexedDB 索引查询远胜 localStorage。
- **Zustand `persist`**：仅用于**轻量状态**——`settings` 当前值（5 个字段：中文辅助/语速/口音/深色模式/提醒）、UI 临时状态、session token。
- **职责边界一句话**：`persist` 管轻量键值（可直接读写 Dexie，亦可退回 `localStorage`），Dexie 管大实体；两者带 `dirty` 标记，联网后 `sync()` 增量上传。简言之：**设置/UI/会话走 persist(localStorage)，学习大数据走 Dexie**。

### 3.3 云端后端（Supabase 推荐）
| 能力 | Supabase | Firebase（备选） |
|---|---|---|
| 关系数据（社交/UGC） | Postgres + RLS | Firestore |
| 鉴权 | Auth（邮箱/手机/OAuth） | Auth |
| 实时（私信/点赞） | Realtime | Firestore 实时 |
| 存储（导入文件/媒体） | Storage | Storage |
| 优点 | SQL 熟悉、RLS 安全、与 06 实体直映射 | 易扩展、文档模型 |

> **推荐 Supabase**：06 数据模型是关系型（vocab/follow/dm/comment 多对多），Postgres + RLS 最直接；社交 UGC（笔记/评论/关注/私信）天然契合。
> **备选 Firebase**：若团队更熟文档模型或需极强实时，可切换，但需把关系实体扁平化。

**RLS（行级安全）策略**（Phase 2 直接落地）
- **用户私有数据表**（`vocab / daily_plan / diagnose_result / favorite / collection / reading_time_aggregate / achievement / settings`）：以 `user_id = auth.uid()` 做行级隔离，仅本人可读写。
- **公开内容表**（`note / note_like / comment / follow`）：笔记/评论**公开可读**、仅作者可改（写策略 `author_id = auth.uid()`）。
- **私信表**（`dm`）：仅 `sender_id = auth.uid()` 或 `receiver_id = auth.uid()` 可见，他人不可查，且写入受「未回复前 ≤2 条」业务校验约束（见 06 §6.5）。
- 所有表默认 `ENABLE ROW LEVEL SECURITY`，无策略即拒绝。

### 3.4 Linguabase 内容包分发
- 包形态：结构化 JSON（字段见 04 附录 A / 06 §2、§9）。
- 分发：**对象存储（Supabase Storage / CDN）**，首次联网全量下载到 IndexedDB，后续按 `version` 增量更新。
- 校验：首次诊断须联网校验（防本地篡改，见 05 问题1）；重诊断用本地包。
- **包体积与增量机制**：Linguabase 包预估 **5–20MB**（字母 + 音标 + 高频词 + 句型 + 诊断题，纯 JSON + 音频路径；音频**按需懒加载**，不随包一次性下载）。增量更新采用 **`version` 标记全量替换 JSON（不做 diff patch，简单可靠）**；音频文件按 `audio_path` 懒加载并缓存到本地，避免首包过大拖慢首次下载体验。

## 4. 语音能力：TTS（点读 / 慢速 / 发音）

| 场景 | 方案 | 离线 | 说明 |
|---|---|---|---|
| 字母/音标/单词/句型发音 | **Linguabase `audio_path` 预录音频** | ✅（预缓存） | 零基础音质最佳，优先于 TTS |
| 慢速播放 | 预录慢速音轨 或 `playbackRate=0.7` | ✅ | 有慢速音轨用音轨，否则降速 |
| 阅读/听书（导入文件有音） | 导入文件本身音频 | ✅ | 非 Linguabase（见 05 §5.5） |
| 阅读纯文本（无音） | **TTS** | ⚠️ 视引擎 | 见下 |

**TTS 引擎选型**
| 引擎 | 类型 | 离线 | 推荐度 |
|---|---|---|---|
| **浏览器 Web Speech API（SpeechSynthesis）** | 端侧/系统 | ⚠️ 依赖系统嗓音 | MVP 兜底，免费、零接入 |
| **云端 TTS（Azure / Google / Edge TTS）** | 云 | ❌ | 音质稳、可预生成缓存；MVP 后接 |
| **离线 TTS 引擎（如 flutter_tts/端侧模型）** | 端侧 | ✅ | App 化后考虑 |

> MVP 策略：发音以 Linguabase 预录音频为主；纯文本兜底用 Web Speech API；Phase 2 用云端 TTS 预生成并缓存，保证零基础发音稳定。

## 5. 语音能力：ASR（跟读评分 / 纠错）

| 场景 | 需求 | 方案 | 离线 |
|---|---|---|---|
| 单词/句子跟读 | 录音→转写→比对原句→准确度评分+纠错 | 见下 | 部分 |

**ASR 选型**
| 引擎 | 类型 | 发音评分 | 推荐度 |
|---|---|---|---|
| **浏览器 Web Speech API（SpeechRecognition）** | 端侧/云 | ✗ 仅转写 | MVP 初版（Chrome 限） |
| **Azure Speech — Pronunciation Assessment** | 云 | ✅ 音素级准确度+纠错 | **推荐 Phase 2**（零基础最需音素反馈） |
| **Google Speech-to-Text + 自比** | 云 | △ 需自算 | 备选 |
| **ELSA / 类似发音评测 API** | 云 | ✅ | 备选（专攻发音） |

> 跟读评分是零基础「敢开口」的核心。MVP 用 Web Speech API 做可用初版（仅转写+字符串比对给粗评分）；**Phase 2 接 Azure Pronunciation Assessment** 给出音素级准确度与纠错，对齐 05 `FollowEval` 浮层。离线时本地录音回放对比（05 已定）。

## 6. AI 能力（解释 / 纠错 / 造句校验 / 翻译 / 对话陪练）

> 注：AI 独立 Tab 已去（见 IA），能力通过「首页搜索切 AI 模式」+ 上下文「问 AI」触达（05 §2.2）。

| 场景 | 调用 | 离线 |
|---|---|---|
| 解释单词 / 纠错 | LLM | ❌ |
| 运用层造 2 句 + 查语法句义 | LLM（见 06 `apply_attempt`） | ⚠️ 缓存最近结果，禁用新校验 |
| 笔记评论中英翻译 | 翻译 API / LLM | ❌ |
| 简单对话陪练 | LLM | ❌ |

**LLM 选型**
| 模型 | 特点 | 推荐度 |
|---|---|---|
| **DeepSeek / 通义千问 / 智谱 GLM** | 中文母语友好、成本低、国内合规 | **推荐（主）** |
| **GPT-4o / Claude** | 能力强、英文地道 | 备选（高质量场景） |
| **Gemini** | 多模态 | 备选 |
| 轻量规则 + 小模型 | MVP 初版（解释/纠错先用规则） | Phase 0 |

> MVP 策略：先用**规则 + 模板**覆盖高频解释/纠错（零基础句子短、可控）；Phase 2 接 LLM（国内模型为主，兼顾合规与成本）。运用层校验是 LLM 强依赖，离线按 05/06 缓存策略降级。

**翻译 API**：DeepL / Google Translate / 模型自带翻译，用于笔记评论中英互译。

## 7. 离线架构（对齐 04 附录 B）

- **本地优先**：内容包 + 学习态全落 IndexedDB，✅完全离线可用（卡片/知识卡/复习/错题本/闯关）。
- **联网后端**：社交/导入解析/诊断首检/搜索AI/私信 → ❌ OfflineGate 拦截，显示「信号迷路了，连上网继续学！」。
- **部分离线**：个人中心/成就墙/设置 → ⚠️ 本地可读写，联网同步。
- **同步**：Zustand `dirty` 标记 → 联网 `sync()` 增量上传；冲突以「本地最新写入」为准（单人学习数据，冲突少）。
- **网络层封装**：统一 `api()` 拦截离线，自动路由 OfflineGate 或本地缓存。

## 8. 跨端打包（后续 App / 小程序）

| 目标 | 方案 | 说明 |
|---|---|---|
| iOS / Android App | **Capacitor** | 包裹同一 Web App，复用 React 代码，原生插件（麦克风/通知） |
| 微信小程序 MVP | **Taro（React 语法）** 或 单独小程序 | 若先做小程序，用 Taro 复用组件逻辑 |
| PWA | 内置（Vite PWA 插件） | 离线缓存 + 桌面图标，Web App 即装即用 |

> 推荐顺序：先 Web App（Vite + PWA）→ Capacitor 出 App → 视需求用 Taro 出小程序。麦克风/ASR 在 App 内需原生权限（Capacitor 插件）。

## 9. 技术风险与缓解

| 风险 | 缓解 |
|---|---|
| 浏览器 ASR 仅 Chrome、英文限 | MVP 粗评分；Phase 2 接 Azure Pronunciation Assessment |
| Web Speech TTS 音质/嗓音不稳 | 主用 Linguabase 预录音频；云端 TTS 预生成缓存 |
| LLM 成本/合规 | 国内模型为主；MVP 先用规则降级 |
| 离线数据冲突 | 单人数据，本地最新写入为准 + dirty 同步 |
| Linguabase 包字段缺失 | 字段映射+降级策略（04 附录 A），绝不展示半成品 |
| 小程序 React 兼容 | Taro 已支持 shadcn 风格组件，或单独小程序 |
